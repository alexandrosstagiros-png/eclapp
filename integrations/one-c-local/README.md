# Локальный тест обмена с 1С

Адрес экрана: **http://127.0.0.1:18414**. Нажатие «Обновить из 1С» заново читает существующую базу `/Users/victor/Documents/InfoBase`. База не копировалась. Рабочий сайт компании не изменялся.

## Что подключено

Первый этап — чтение данных через реальный интерфейс OData платформы 1С 8.5.1.1150 и преобразование в контракт `transport.local-test.v1`. Экран показывает водителей, автомобили, заявки, смены и назначения со стабильными идентификаторами 1С. Это отдельный локальный экран проверки обмена в проекте ЕЦЛ; импорт в PostgreSQL основного приложения и связь кандидатов с водителями пока не реализованы.

В исходной базе изменён только состав стандартного интерфейса OData: добавлены `Справочник.Водители`, `Справочник.ТранспортныеСредства`, `Справочник.Клиенты`, `Справочник.ПроектыКлиентов`, `Документ.СменаТранспорта`, `Документ.ЗаявкаКлиента`. До настройки состав был пустым, после — шесть объектов. Настройка выполнена внешней обработкой; основная конфигурация не заменялась. Справочники и документы обработка не записывает.

Экран и адаптер только читают бизнес-данные. В самой платформе опубликован стандартный OData, который технически поддерживает и запись: ограничение чтением относится к этому адаптеру, а не является новой ролью доступа в 1С. Серверы слушают только `127.0.0.1`, веб-клиент и прямой/SSH-доступ автономного сервера отключены. Регламентные задания автономного сервера отключены. Публикацию нельзя переносить в сеть в таком виде; для корпоративного подключения нужны отдельный пользователь с нужными правами и настройки среды внедрения.

## Как пользоваться

1. Откройте `Запустить тест.command` (или выполните `node integrations/one-c-local/manage.cjs start` из корня проекта).
2. Откройте http://127.0.0.1:18414 и нажмите «Обновить из 1С».
3. Переключайте вкладки, используйте поиск и диапазон дат. Первые найденные данные — прежние демонстрационные записи мая 2026 года, поэтому начальные фильтры дат пустые.
4. Измените нужную тестовую запись в обычном клиенте 1С, сохраните её, затем снова обновите экран обмена.
5. Для остановки откройте `Остановить тест.command` или выполните `node integrations/one-c-local/manage.cjs stop`. После остановки можно выполнять операции Конфигуратора, требующие исключительного доступа к базе.

Первый запуск платформы под Rosetta после настройки занял около двух минут; последующие чтения заняли секунды. При открытии экрана или обновлении данных web-сервер проверяет процесс 1С и запускает его, если тот завершился. Чтение ожидает готовности с общим пределом две минуты. Автозапуск при входе в macOS не устанавливается: после перезагрузки нужно один раз открыть `Запустить тест.command`.

Команды запуска не создают новую информационную базу и не завершают посторонние процессы, занявшие порты. Сведения о собственных процессах находятся в `.local/one-c-local/processes.json`.

## Значение показателей

- «Выход»: флаг `ВышелНаЛинию` в строке смены; статусы `Неподача`, `Отменен`, `Заменен` и флаг `ЕстьНеподача` исключают строку из итога. Противоречия выводятся замечаниями.
- «Назначения с выполненной заявкой»: присутствует водитель, есть выход и связанная заявка в статусе `Выполнена` с заполненным корректным интервалом фактического времени. Это производный признак выполнения заказа, не подтверждение индивидуально отработанной смены или основание для зарплаты.
- Связь водитель → заявка берётся из табличной части `СменаТранспорта.РесурсыСмены`; у заявки прямого реквизита водителя нет.
- Нулевые ссылки/даты не превращаются в вымышленные данные. Документы с пометкой удаления исключены. Читаются все страницы, максимум 10 000 объектов каждого вида; превышение выдаёт ошибку без молчаливого усечения.
- Даты документов сохраняют локальное время 1С. `fetchedAt` — момент получения набора в UTC.

## Файлы и повторная настройка

- `adapter.cjs` — чтение шести наборов и нормализация; источник фиксирован на loopback.
- `server.cjs`, `public/` — локальный API и экран.
- `manage.cjs` — запуск, статус и остановка двух процессов.
- `build-setup-epf.mjs` — воспроизводимый генератор внешней обработки настройки состава OData. Повторное выполнение сохраняет существующий состав и не добавляет дубликаты.
- `ibsrv.example.yml` — образец настроек. Активный файл: `.local/one-c-local/ibsrv.yml`.
- `.local/one-c-local/latest.json` — последний полностью полученный набор, файл с правами `0600`. Не используется как успешный ответ при недоступной 1С. Папка `.local` исключена из Git.

Для повторной сборки внешней обработки (сервер теста должен быть остановлен; команды выполняются из корня проекта):

```sh
node integrations/one-c-local/build-setup-epf.mjs \
  "$PWD/.local/one-c-local/setup-source" \
  "$PWD/.local/one-c-local/setup.marker"
/opt/1cv8/8.5.1.1150/ibcmd config import \
  --db-path='/Users/victor/Documents/InfoBase' \
  --data="$PWD/.local/one-c-local/admin-data" \
  --out="$PWD/.local/one-c-local/setup.epf" \
  "$PWD/.local/one-c-local/setup-source/LocalIntegrationODataSetup.xml"
/opt/1cv8/8.5.1.1150/1cv8 ENTERPRISE \
  /F '/Users/victor/Documents/InfoBase' \
  /Execute "$PWD/.local/one-c-local/setup.epf" \
  /DisableStartupMessages /DisableStartupDialogs \
  /Out "$PWD/.local/one-c-local/setup-run.log"
```

Успех проверяется свежим `setup.marker` (`status=ok`, список шести `verified=`) и реальным чтением OData. Старый маркер не является подтверждением нового запуска.

## Исправление запуска 19 сентября 2026

При диагностике работал процесс экрана, но процесс автономного сервера 1С отсутствовал. Первоначальный экземпляр был запущен в сессии настройки; новый запускается как независимый процесс с журналом `.local/one-c-local/ibsrv.log`.

Добавлено восстановление отсутствующего источника при чтении, ожидание фактических данных вместо одной проверки PID и отмена ожидания при остановке экрана. Одновременные обновления используют одно чтение; запуск из CLI и web защищён общей блокировкой. Чужой процесс на порту не завершается. Тайм-аут применяется ко всему чтению, а ошибки доступа и схемы не маскируются повторными попытками.

Проверка: `node --test integrations/one-c-local/adapter.test.cjs integrations/one-c-local/recovery.test.cjs` — 36 тестов. После остановки процесса источника два одновременных запроса успешно восстановили подключение за 32 секунды: оба HTTP 200, один новый процесс 1С, одинаковый момент чтения и прежние количества 2/2/2/2. Результат — `.local/one-c-local/recovery-verification.json`. Открытая страница обновлена и показала данные без ошибки.
