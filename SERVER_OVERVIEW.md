## Модули API

- `identity-access`: вход, сотрудники, роли и ограничения доступа.
- `operations`: рейсы.
- `workflow`: документы и связанные процессы.
- `finance`: финансы, тарифы, начисления, депозиты.
- `inspections`: осмотры и фотографии.
- `communications`: обращения и Telegram-интеграция.

API использует префикс `/api/v1`. Развёрнутые контроллеры: `apps/api/dist/modules/*/interface/*controller.js`. Общая конфигурация и запуск: `apps/api/dist/platform/config.js`, `apps/api/dist/bootstrap.js`, `apps/api/dist/main.js`.

## Проверенное состояние

- `GET /` → HTTP 200; сертификат проходит проверку TLS.
- `GET /api/v1/health/live` → HTTP 200, `{"status":"ok"}`.
- `GET /api/v1/health/ready` → HTTP 200, `{"status":"ok"}`; проверяется доступ к таблицам БД.
- `GET /api/v1/trips` без авторизации → HTTP 401, `UNAUTHENTICATED`.
- Оба сервиса приложения активны; счётчик автоматических перезапусков `NRestarts=0`. Сервисов в состоянии failed не обнаружено.
- Использовано около 556 МиБ из 1,8 ГиБ RAM, доступно около 1,3 ГиБ. Диск занят на 13%: 4,7 ГиБ из 40 ГиБ. Это показатели на момент осмотра.
- Сертификат Let's Encrypt действителен до 22 сентября 2026 года, 03:57 UTC. Таймер автоматического продления активен; последняя служба продления завершилась успешно.

## Активные настройки

- Публичный API: `NODE_ENV=production`, `DEV_AUTH_ENABLED=false`, `DEMO_AUTH_ENABLED=false`.
- `TELEGRAM_ONBOARDING_ENABLED=true`.
- `DEMO_EMPLOYEE_CREATION_ENABLED=true` — назначение этого флага следует учитывать при дальнейшей работе с сотрудниками.
- `TELEGRAM_COMMUNICATIONS_ENABLED=false`, `ONE_C_HTTP_ENABLED=false`: внешняя отправка уведомлений и HTTP-обмен с 1С отключены.
- Публичный API и БД слушают loopback; внешние подключения проходят через Nginx.
- Сервисы работают под отдельными системными пользователями с `ProtectSystem=strict`, `ProtectHome=yes`, `NoNewPrivileges=yes`.

## Данные и резервные копии

Оба API настроены на одну PostgreSQL-базу `transport` и одну роль `transport_app` на `127.0.0.1`. Следовательно, закрытое демо нельзя считать изолированной копией данных публичного Mini App; перед изменениями и запуском служебных сценариев нужно учитывать общую базу.

Обнаружены резервные копии БД в `/opt/transport-demo/.local/backups` и `/var/backups/transport-miniapp`. Самая новая из найденных при осмотре этих каталогов — `/var/backups/transport-miniapp/post-016.30m8yCXG/.local/backups/transport-2026-09-12T13-43-58-149Z.dump` (12 сентября 2026 года, 13:43 UTC, около 535 КиБ). Восстановление при текущем ознакомлении не проверялось.

В просмотренных systemd-таймерах и системных/пользовательских crontab расписание резервного копирования приложения не найдено. Это не исключает резервного копирования вне сервера или другим механизмом.
