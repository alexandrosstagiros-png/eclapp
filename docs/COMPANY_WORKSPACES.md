# Общая Команда и Рекрутинг

Обновлено 26 сентября 2026. Компания определяется юридическим лицом из действующих полномочий сотрудника; проекты больше не разделяют общую переписку и внутреннюю базу подбора. Рабочие разделы открываются без выбора технического проекта. Они объединяют данные, к которым сотрудник уже имеет доступ; права не расширяются.

## Команда

Открытые каналы всех проектов компании собраны в одном списке. Убраны «Область команды» и повторный выбор проекта для общения. Только администратор закрывает канал и задаёт аудиторию; создателя тоже можно исключить. Исторические закрытые каналы не опубликованы заново. Личные диалоги сохраняют прежнюю приватность и административный аудит.

База знаний объединяет материалы исходных доступных проектов с сохранением ограничений статей. Задачи, итоги, сводки и запросы водителей собираются в общие списки с сохранением исходных прав и связей записей.

## Рекрутинг

Показаны кандидаты всех рекрутеров компании. Выбор технического проекта убран из фильтров, карточек и оформления. Один кандидат может участвовать в разных подборах; новая карточка человека для каждого подбора не создаётся. Контакты, задачи, СБ и выходы сохраняют связь с нужной потребностью.

Новые дубликаты телефона внутри компании блокируются; исторические записи с одинаковым телефоном сохранены. Внешний рекрутер продолжает видеть только назначенные потребности и свои разрешённые записи. Ручное создание/подключение внешних аккаунтов сохраняет прежние полномочия управления сотрудниками; приглашения доступны по проектам компании.

Миграция `054_company_recruitment.sql` меняет связи кандидата с подборами, задачами и контактами на уровень компании; строки не перемещает и не объединяет. Удаление переключателей 26 сентября не требует новой миграции: существующие идентификаторы сохраняются для доступа и обмена с 1С.

## Остальные рабочие разделы

Тендеры, разработка и автопарк показывают доступные записи вместе. Изменения отправляются в исходный контекст записи. В планировании доступны сохранённые планы на дату, а новое назначение определяется выбранным водителем. В календаре можно открыть сохранённые планы за период. Создание рейса определяет контекст по совместимым водителю и автомобилю; загрузка реестра — по номерам рейсов. Реестр из нескольких контекстов требует разделения файла, чтобы не привязать финансовые строки к неверному договору.

Административные настройки разрешений остаются отдельными: удаление рабочего переключателя не выдаёт сотрудникам новые права.

## Проверка

- `npm run test:workspace:browser` — работа без выбора технического проекта, сохранение исходных связей, создание в заполненном рабочем контексте, оргструктура и совместимость форм оформления.
- `npm run test:company` — доступ между проектами одной компании, запрет чужой компании, административная аудитория, отзыв прав, переход кандидата между проектами, внешние ограничения.
- `npm run test:team:company:browser` и `npm run test:recruitment:company:browser` — общий список, сохранение исходных связей, карточки, задержанные ответы, мобильная вёрстка.
- Дополнительно прошли браузерные сценарии закрытых каналов, внешнего рекрутинга, импорта Excel, напоминаний и рабочего процесса подбора.

Проверено в постоянном локальном приложении http://127.0.0.1:18514. Контрольная сумма миграции совпала с исходником, общее число активных кандидатов совпало с базой, новые рабочие записи при проверке не создавались. Протокол: `.local/company-workspaces-verification.json`. Публичный сервер этой задачей не обновлялся.

После обновления 26 сентября локальное приложение перезапущено. Подтверждены отсутствие переключателя в планировании, автоматический выбор заполненного контекста рекрутинга и совпадение количества строк и сумм общей аналитики автопарка с исходными доступными данными. Рабочие записи при проверке не создавались. Протокол: `.local/unified-workspace-verification.json`.
