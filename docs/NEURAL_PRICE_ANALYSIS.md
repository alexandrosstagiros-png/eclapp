# Анализ цен заказ-нарядов

Кнопка «Проверить адекватность цен» доступна в разделе «Нейросети», в карточке сохранённого заказ-наряда и в подробностях импортированной позиции. В разделе «Нейросети» выбираются финансовая область и заказ-наряд; поиск работает по номеру, ID и госномеру. Несохранённые изменения карточки нужно сохранить перед анализом.

Сервер использует активную загрузку и актуальные заказ-наряды ЕЦЛ выбранной области. Доступ требует действующей сессии, одной из ролей `access_admin`, `manager`, `mechanic`, `auditor` и текущего разрешения `financeVisible` для полного набора области. Данные других областей не становятся источником сравнения.

Для каждой позиции фактическая сумма делится на количество, включая скидки и корректировки. Сравниваются завершённые заказ-наряды за 365 дней до даты проверяемого документа. Должны совпадать нормализованные наименование, тип, единица измерения, бренд детали, бренд и группа автомобиля, валюта и признак выполнения своими силами. Каждому отдельному историческому заказ-наряду соответствует одна цена: сумма его сопоставимых строк / общее количество. Проверяемый заказ-наряд исключается из истории.

При наличии минимум трёх исторических заказ-нарядов рассчитываются медиана, минимум, максимум и отклонение. Отклонения строго выше +25% и ниже −25% отмечаются отдельно. При недостатке сопоставимых документов, отсутствии корректной даты, положительных сумм/количеств или единиц измерения показывается «Недостаточно данных». До пяти примеров подтверждают основание сравнения. Историческая цена не доказывает текущую рыночную цену; отклонение служит поводом проверить комплектацию, работы и документы.

Настроенная задача `work_order_prices` добавляет текстовое пояснение выбранной модели через `NeuralService`. Модель получает рассчитанные показатели и примеры максимум для 100 позиций, с явным числом пропущенных позиций. Локальная таблица содержит до 1 000 позиций документа. Токены, модель и рассчитанная стоимость приходят из общей системы учёта нейросетей. Без настроенной модели сравнение выполняется локально без токенов. Сбой провайдера оставляет исторический результат доступным и показывает сообщение о недоступном комментарии. Ошибки доступа не маскируются.

API:

- `GET /api/v1/fleet-maintenance/price-analysis/orders?responsibilityScopeId=<UUID>&search=<строка>` — до 500 найденных документов и общее число.
- `POST /api/v1/fleet-maintenance/price-analysis` с `{responsibilityScopeId, orderId}` — методика, ограничения, сводка, позиции с доказательствами, `ai` и `aiWarning`. ID нативного документа имеет вид `app:<UUID>`.

Проверки: `tests/fleet-price-analysis.test.cjs`, `tests/fleet-price-analysis-integration.test.cjs`, `tests/fleet-price-analysis-browser.cjs`. Интеграция и браузер используют отдельный PostgreSQL с синтетическими данными.
