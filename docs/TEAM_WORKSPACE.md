# Команда

Корпоративное общение встроено в существующее приложение ЕЦЛ: раздел «Команда», прямая ссылка `?section=team`. Используются текущие сотрудники и вход. Общение организовано на уровне компании, а привязки к проектам сохранены в записях и специализированных рабочих вкладках.

## Кто видит раздел

«Команда» доступна только внутренним сотрудникам: диспетчеру, менеджеру, штатному рекрутеру, тендерному специалисту, документоведу, механику, администратору и аудитору. Офисный и удалённый формат работы имеют одинаковый доступ. Водитель и внешний рекрутер не видят раздел или его уведомления; прямые ссылки перенаправляются, а все API Команды отклоняют их запросы. Права на проект, финансовые или персональные данные сами по себе не открывают Команду этим двум ролям. Личные настройки профиля остаются доступны.

Проверка: `npm run test:team:staff-access:browser` — восемь разрешённых ролей, два запрета, 17 маршрутов чтения, создание чата/сообщения, меню и прямые ссылки.

## Общение

- Открытые каналы доступны всем штатным сотрудникам компании независимо от их проектов и областей ответственности. Чаты разных компаний изолированы. Только администратор закрывает канал и выбирает его аудиторию.
- Личные чаты доступны двум участникам и администратору компании. Это корпоративная переписка: интерфейс прямо предупреждает о доступе администратора.
- Из любого сообщения можно открыть обсуждение; из ответа — отдельную вложенную ветку. Связи между сообщениями сохраняются в базе.
- Администратор видит также личные чаты, в которых не участвует. Такой просмотр записывается в аудит; отправлять сообщения от лица участников нельзя.
- История загружается порциями. Отправка с повторным идентификатором не создаёт дубликат сообщения.

### Статус прочтения и скорость ответов

У своих сообщений отправитель видит небольшую приглушённую галочку в нижнем правом углу: одна означает «Отправлено», две — наличие прочтения текущей версии. В личном чате это прочтение собеседником; в канале подсказка показывает число прочитавших, без утверждения, что прочитали все. Подсказка доступна при наведении, фокусе или нажатии на индикатор. После редактирования сообщение снова ожидает прочтения новой версии. Удалённые сообщения не показывают статус.

Прочтение фиксируется после фактического показа сообщения на активной вкладке. Свёрнутые ветки не считаются прочитанными. Статусы обновляются при обычном опросе чата (до 12 секунд), даже если новых сообщений нет; учитываются и видимые сообщения из ранее загруженной истории. Просмотр администратором чужой закрытой переписки не считается прочтением её участником.

Вкладка «Скорость ответов» доступна только администратору; вход от имени сотрудника её не открывает. За 7, 30 или 90 дней показаны среднее время, медиана, число ответов и текущие ожидания в личных чатах по каждому доступному внутреннему сотруднику. Есть поиск, сортировка и обновление. Сотрудники без ответов остаются в таблице с прочерком вместо времени. Мобильный вид представляет строки карточками.

В личном чате время считается от первого сообщения подряд от собеседника до первого ответа. В канале учитывается первый явный ответ сотрудника на чужое сообщение через ветку, повторные ответы тому же сообщению не добавляют замеров. Самоответы и удалённые сообщения исключаются. Период выбирает дату ответа: более раннее исходное сообщение сохраняет свой момент начала ожидания. Незакрытые серии в личных чатах показываются, если начались в выбранный период; это не автоматическое назначение задачи или определение вопроса по смыслу. Используется календарное время, включая ночи и выходные.

Статистика охватывает доступные компании и их проекты, как переписка. Сервер проверяет актуальную роль, доступ и сессию; чтение метаданных чужих закрытых переписок фиксируется в аудите. API: `GET /team/response-metrics?days=7|30|90`, необязательный `responsibilityScopeId` ограничивает компанию. Галочки используют точные существующие квитанции `team_message_reads`; миграция `057_team_message_read_status.sql` добавляет индекс, не изменяя переписку.

Проверки: `npm run test:team`, `npm run test:team:response-status:browser`, `npm run build`. Браузерные проверки работают на синтетических аккаунтах и временной PostgreSQL.

25 сентября 2026 функция установлена в локальном приложении `http://127.0.0.1:18514/?section=team`. Перед обновлением сохранена холодная копия `.local/backups/team-response-status-2026-09-25T16-39-49.206Z`: 2 087 файлов проверены по SHA-256. Переписка, участники, инструкции, профили и прежние отметки прочтения сохранились; сверены число записей и контрольные суммы содержимого. Миграция 057 и API статистики проверены после перезапуска. Протокол: `.local/team-response-status-installation.json`. Публичный сервер не обновлялся.

### Файлы в переписке

Кнопка «+» доступна в каналах, личных чатах и ветках. К одному сообщению можно добавить до пяти файлов общим размером 25 МиБ. Перед отправкой видны имена и размеры; ненужные файлы можно удалить из черновика. Текст необязателен. При ошибке отправки текст и выбранные файлы остаются в черновике для повторной попытки.

«Фото и файлы» уменьшает обычные фотографии до 1 920 пикселей по длинной стороне и подбирает качество JPEG с целевым размером до 1 МиБ. Уже оптимизированное фото сохраняется, если перекодирование только увеличивает размер. Для исходного качества выберите «Файл без сжатия»: байты оригинала сохраняются точно. Неподдерживаемые и анимированные изображения отправляются обычным файлом. Лимит 25 МиБ применяется после обработки; оригиналы для базы знаний имеют отдельный лимит 8 МиБ.

Файлы сохраняются вместе с сообщением в PostgreSQL и входят в обычную резервную копию базы. Нажмите на вложение, чтобы скачать его. Сервер заново проверяет сессию и доступ к исходной переписке; публикация сводки не даёт получателю права скачивать файлы из чужого личного чата. Административное скачивание из чужой переписки фиксируется в аудите. Вложения выдаются как скачиваемые файлы, без исполнения их содержимого в приложении.

Автосводки пока анализируют текст сообщений: содержимое прикреплённых документов не распознаётся и не включается в анализ.

### Панель сообщения

- «Аа» открывает форматирование: жирный, курсив, зачёркивание, код, цитата, списки и ссылка. Форматирование отображается безопасно, без исполнения HTML.
- Эмодзи вставляются в текущую позицию текста.
- «@» или ввод символа в тексте открывает выбор сотрудника. «@all» отмечает доступных участников текущего канала или личного чата. Уведомления появляются во вкладке «Упоминания» со счётчиком непрочитанных и ссылкой на исходное сообщение. Получатели фиксируются при отправке; появление нового сотрудника не создаёт ему старые уведомления. Внешние push-уведомления не отправляются.
- Камера записывает обычное видео до 720p или кружок 480 × 480, до одной минуты, с уменьшенным битрейтом. Размер одной записи ограничен 8 МиБ.
- Микрофон предлагает два отдельных режима: голосовое сообщение до пяти минут или диктовка текста. Запись сначала открывается в предпросмотре; для отправки нужно прикрепить её к черновику и отправить сообщение.
- «/» предлагает шаблоны `/task`, `/decision`, `/question`, `/shrug` и справку `/help`. Команды вставляют текст в черновик, не создают задачи или сообщения автоматически.
- Enter отправляет сообщение, Shift + Enter добавляет строку.

Камера и микрофон включаются только после нажатия «Начать запись»; при закрытии окна или смене чата захват прекращается. Требуются разрешение браузера и защищённое соединение либо localhost. Диктовка использует SpeechRecognition браузера и доступна только при его поддержке; браузер может передавать речь своему сервису распознавания, о чём сообщается перед началом. Качество распознавания зависит от браузера и его сервиса.

## База знаний

Новые статьи создаются по обязательной структуре: «Для кого» (одна или несколько должностей компании), «Тема», «Причина создания», «Задача создания», «Текст», «Результат». Автором навсегда остаётся сотрудник, впервые сохранивший статью. Дата создания выставляется сервером; версия начинается с 1 и увеличивается при сохранении правок. Поле «Отредактировал» показывается только для последнего редактора, отличающегося от автора. Автор, дата и версия вручную не меняются.

Должности берутся из оргструктуры компании выбранного проекта. Администратор может добавить должность прямо в редакторе, сохранив черновик. Поле «Для кого» описывает аудиторию и не заменяет права доступа к базе знаний. Поиск учитывает все поля инструкции и выбранные должности. При конфликте версий сохраняется весь черновик, включая аудиторию, причину, задачу и результат.

Структурированные статьи требуют миграции `059_team_structured_articles.sql`. Ранее созданные и импортированные инструкции сохраняют свои тексты и привычное редактирование; обязательный новый шаблон применяется к новым статьям. Полная передача новых полей через API переводит старую статью в структурированный формат.

Проверки нового шаблона: `npm run test:team:knowledge:structured` и `npm run test:team:knowledge:structured:browser`. Они проверяют обязательные поля, должности компании, автоматические метаданные, сохранение черновика при конфликте и работу формы на телефоне.

В общем списке одинаковые импортированные материалы из нескольких доступных областей показываются один раз. Совпадать должны текущие название и текст, папка, видимость и исходный файл; разные редакции и материалы в разных папках остаются отдельными. Объединение выполняется после проверки доступа, а скачивание и редактирование используют исходную запись выбранной доступной копии. Записи областей и отметки ознакомления для адаптации сохраняются.

Проверки объединённого списка: `npm run test:team:knowledge` и `npm run test:team:knowledge:dedup:browser` (счётчики, поиск, страницы и отображение инструкций на компьютере и мобильном экране).

Администратор удаляет инструкцию через меню «⋯ → Удалить инструкцию» с отдельным подтверждением. Для импортированного материала удаляются также его точные копии в областях, к которым у администратора есть доступ; изменённые редакции остаются отдельными. Удалённые инструкции исчезают из общего списка, поиска и адаптации, скачивание оригинала и повторное сохранение запрещены. История операций и прежние отметки ознакомления сохраняются. Право редактирования само по себе не даёт права удаления, а в режиме входа за сотрудника удаление недоступно.

Удаление инструкций требует миграции `058_team_article_deletion.sql` и перезапуска локального API. Если удалены все назначенные инструкции, сотрудник может завершить адаптацию. Изначально пустая программа по-прежнему ожидает назначения материалов.

Проверки удаления: `npm run test:team:knowledge:deletion` и `npm run test:team:knowledge:deletion:browser`. Сценарии выполняются на временных документах и проверяют ограничения прав, повтор запроса, конфликт версий, отмену, удаление копий и мобильное подтверждение.

Чтение базы знаний и права на изменение разделены. Администратор открывает «База знаний → Права на инструкции» и отдельно выдаёт сотруднику права создания и редактирования в выбранной рабочей области. По умолчанию эти права у сотрудников выключены; администратор имеет оба права. Сервер проверяет разрешение при каждом сохранении, а изменение прав фиксирует в журнале аудита. Проверка версии защищает от перезаписи параллельных правок.

Импортированные материалы сгруппированы по исходным папкам. Выбор родительской папки включает подпапки; поиск учитывает название, текст, путь и имя оригинала. Список разбит на страницы. В базе знаний показывается текст инструкции без блока «Скачать оригинал», имени файла и размера. Исходные файлы сохраняются в системе; в программе адаптации их скачивание доступно с повторной проверкой доступа. Импортированные инструкции редактирует администратор или сотрудник с правом редактирования; изменение текста статьи сохраняет исходный файл. Материал может быть доступен всем сотрудникам выбранной области, сотрудникам кроме водителей или только её администраторам. Редакторское право само по себе не открывает скрытые материалы. При входе администратора от имени водителя весь раздел «Команда» и его база знаний недоступны.

### Адаптация нового сотрудника

В формах создания внутреннего сотрудника есть необязательная галочка «Нужна программа адаптации». Она выключена при каждом открытии новой формы; существующим сотрудникам адаптация не назначается. Задание привязывается к области работы нового сотрудника и сохраняется в той же транзакции, что и учётная запись. Повтор запроса создания не сбрасывает прочитанные материалы и завершение программы.

При входе сотрудника с незавершённой программой сначала открывается «Команда → Адаптация». В неё включаются инструкции из корневых папок «Общая информация» и «Папка сотрудника компании» вместе с подпапками. Сотрудник читает материалы и отмечает прочтение. Прогресс хранится на сервере, а завершить программу можно после прочтения всех доступных инструкций. При изменении текста до завершения требуется прочитать новую версию. После завершения программа доступна для перечитывания, автоматическое открытие прекращается. Программа не блокирует остальные рабочие разделы.

Для водителей и внешних рекрутеров эта программа не назначается; адаптация не предоставляет дополнительных прав чтения документов.

Протокол установки: `.local/team-knowledge-installation.json`. Проверки: 55 серверных сценариев команды; общий модульный набор — 218 успешных и один предусмотренный пропуск. ## Сводки

Сводки и расписания сводок теперь находятся в разделе **«Нейросети»**. Доступна публикация в выбранный чат команды вручную и по расписанию. Подключение моделей и учёт расходов описаны в [Нейросетях](NEURAL.md).

Администратор выбирает период и формирует сводку по всем каналам, личным чатам и вложенным веткам выбранной области, включая чаты, в которых он не участвует. Новая сводка закрыта от сотрудников; администратор явно выбирает получателей и может отозвать доступ.

Получателю передаётся содержимое сводки, включая попавшие в неё выдержки из переписки. Это не добавляет получателю права читать исходный личный чат. Перед публикацией администратор должен просмотреть содержание и список получателей.

Четыре категории: задачи, возможности роста, оптимизация, угрозы. Локальный режим подбирает исходные выдержки по текстовым признакам, с количеством обработанных сообщений и ссылками на источники. Если администратор назначил модель задаче сводки, переписка передаётся выбранному провайдеру для обзорного текста; категории сохраняют исходные выдержки. Категории и выводы требуют проверки.

## Расписание

Администратор задаёт ежедневную или еженедельную сводку, время, часовой пояс и получателей. Расписание хранится в PostgreSQL и исполняется сервером, независимо от открытой вкладки. Выключенный сервер не может выполнять задания; после запуска обработчик проверяет сохранённые сроки. Результаты доступны внутри приложения; внешние рассылки не включаются.

## Редактирование, реакции и ограничение частоты

В «Команде» автор может редактировать и удалять собственные сообщения в каналах, личных чатах и ветках. Администратор может менять и удалять сообщения других авторов в доступных ему областях, включая просмотр чужих личных чатов. Вход администратора от имени сотрудника таких дополнительных прав не даёт. Изменения проверяют текущую версию; при конфликте черновик остаётся в редакторе для сравнения. Первоначальный запрос отправки и журнал операций сохраняются отдельно: повтор после сетевой ошибки не создаёт копию и не восстанавливает удалённое сообщение.

Удалённое сообщение показывается как «Сообщение удалено»: текст, вложения, упоминания и реакции скрыты, скачать вложение нельзя. Дочерние ветки остаются доступными. Новые сводки не включают удалённый текст; уже созданные сводки являются сохранёнными снимками и не переписываются. Оригинал отправки хранится в служебной истории, недоступной через пользовательские маршруты. Участники могут поставить и снять реакции 👍 ❤️ 😂 🎉 👀 ✅ 🙏; счётчики обновляются у открытых клиентов вместе с правками старых сообщений.

Администратор включает «Антиконфликтный режим» в выбранном канале или личном чате на один час. В течение часа сотрудник отправляет не более одного сообщения в пять минут суммарно в этом разговоре и его ветках. Администратор ограничению не подчиняется и может отключить режим досрочно. Окончание и интервалы проверяет сервер; перезагрузка, другая вкладка и прямой API-запрос ограничение не обходят. Редактирование и реакции не считаются новыми сообщениями. Пятиминутный интервал применяется и к уже включённому режиму, сохраняя прежний срок его окончания.

## Закрытые чаты

Только администратор может создать закрытый канал, открыть «Доступ к чату», изменить состав участников или переключить существующий канал между открытым и закрытым режимом. Создатель канала не получает дополнительных прав на управление видимостью; администратор может исключить его из аудитории. Участников можно выбирать среди действующих сотрудников всей компании, в том числе работающих в других проектах. Личные диалоги сохраняют прежнюю приватность: доступны двум собеседникам и администратору, состав неизменяем.

Посторонние сотрудники не видят закрытый канал в списке и поиске, не получают упоминания из него и не могут открыть сообщения, ветки или вложения по прямой ссылке. Исключение участника закрывает ему доступ и к прежней истории. Открытый интерфейс повторно проверяет права при обновлении и убирает недоступную переписку. Доступ дополнительно ограничен компанией и действующей учётной записью. После отзыва последнего доступа к компании сотрудник теряет доступ ко всей её переписке.

Сохраняется ранее заданное правило корпоративной среды: администратор видит закрытые каналы своей компании, с записью такого просмотра в аудит. Администратор, не включённый в участников закрытого канала, не отправляет в него сообщения от имени участников. Он может управлять доступом и редактировать или удалять сообщения.

Сводка — отдельная копия выбранных выдержек. Администратор по-прежнему может явно поделиться ею, в том числе по настроенному расписанию, с сотрудниками вне закрытого чата. Это не открывает исходный чат, сообщения или вложения. Уже опубликованные сводки остаются доступны назначенным получателям до отзыва доступа к самой сводке. В интерфейсе закрытого чата и при настройке сводок это правило показано пользователю.

Обычный короткий тап открывает канал, движение до длительного нажатия сохраняет прокрутку, Escape отменяет перенос. В меню также доступны «Переместить выше» и «Переместить ниже». Общий порядок каналов компании сохраняется на сервере; новые сообщения больше не переставляют каналы. У личных и архивных чатов перетаскивания нет.

«Архивировать канал» после подтверждения переносит его в отдельный блок «Архив каналов» у участников. История и вложения остаются доступны с прежними правами, но сообщения, правки и реакции запрещены. Архив не создаёт непрочитанных уведомлений. Администратор может вернуть канал из архива; его прежнее место в порядке сохраняется.

«Удалить канал» требует отдельного подтверждения. Канал, сообщения и вложения перестают быть доступны пользователям, включая администратора; восстановление через интерфейс и API запрещено. В базе остаётся запись удаления для аудита и целостности существующих ссылок. Проверки прав, версии и повторных операций выполняются на сервере.

Изменение требует миграции `056_team_channel_management.sql` вместе с новой серверной и клиентской сборкой. В постоянном локальном приложении изменения серверного кода и миграции начинают действовать после штатного перезапуска `integrations/local-app/manage.cjs stop` / `start`; одного обновления страницы недостаточно. Проверки: `npm run test:team:channels`, `npm run test:team:channels:browser` и `npm run test:team:channels:drag:browser`.

## Непрочитанные, уведомления и личный профиль

Для каждого чата хранятся отдельные счётчики непрочитанных сообщений и непрочитанных упоминаний. Прочтение подтверждает конкретные показанные версии сообщений после их видимости на экране: скрытые ветки и фоновая вкладка не подтверждают сообщения. Новое упоминание в изменённом сообщении снова становится непрочитанным, обычное редактирование не возвращает весь текст в непрочитанное. Прежние подтверждения упоминаний сохраняются миграцией 050.

В заголовке приложения доступен центр уведомлений команды по всем разрешённым областям. Он работает, пока приложение открыто, и переходит к исходному сообщению с повторной проверкой прав. Пользователь может скрыть обычные всплывающие уведомления и отдельно отключить их звук глобально в «Настройках» либо для одного чата через его кнопку «Уведомления». Общее отключение и отключение чата складываются. Упоминания пользователя и `@all` обходят оба ограничения; счётчики остаются видны всегда. Звук браузера активируется после первого действия пользователя. Операционная система, Telegram и внешние push-сервисы для этих уведомлений не используются.

«Настройки» доступны всем пользователям, включая водителей. Здесь сохраняются фото, почта, контактный телефон и дополнительные контакты. Полную дату рождения видит только администратор, остальные пользователи — день и месяц, в том числе в собственных настройках. Изменения контактов и фотографии сохраняют скрытую дату рождения. Контактный телефон не изменяет номер для входа. Фото JPEG/PNG/WebP автоматически обрезается по центру и пересохраняется в JPEG 512×512 до 128 КБ. Сервер независимо проверяет формат, размер, версию профиля и повторные операции. Фото и контакты коллег в команде доступны только в общей области при разрешении на персональные данные; собственный профиль доступен без этого разрешения. Фото загружаются по требованию с проверкой актуальных прав. Изменения личных полей не записывают их содержимое в аудит.

## Поздравления и видимость дат рождения

Раздел «Поздравления» доступен только администратору вне режима входа за сотрудника. Он показывает сотрудников с днями рождения сегодня, в ближайшие 7 или 30 дней и в течение года. Вкладка и напоминание в кабинете показывают число сегодняшних именинников, которых ещё нужно поздравить. Список обновляется каждую минуту и при возвращении в окно. На вкладке «Без даты» администратор может заполнить даты рождения; существующую дату можно исправить или очистить. Изменение даты сохраняет контакты и фотографию сотрудника и проверяет версию профиля, чтобы не затереть параллельные изменения.

Полная дата рождения доступна администратору; остальные пользователи получают от API и видят в карточках и собственных настройках только день и месяц. Год и возраст им не передаются. В личных настройках обычного сотрудника дата отображается без редактирования, а сохранение остальных полей не затрагивает её. Действующие ограничения доступа к персональным данным и компании сохраняются.

Кнопка «Поздравили» отмечает сегодняшнее поздравление, отметку можно отменить. Она сохраняется отдельно для каждого администратора и ежегодной даты, переживает перезапуск и не переносится на следующий год. Даты рассчитаны по московскому времени. День рождения 29 февраля в невисокосном году напоминается 28 февраля. Учитываются активные одобренные сотрудники, включая водителей; внешние рекрутеры исключены. Число сотрудников без заполненной даты показано отдельно.

## Оргструктура и задачи

Порядок вкладок: «Обсуждения», «Упоминания», «Задачи», «Запросы водителей», «Итоги», далее база знаний и сводки. Администратор на вкладке «Задачи» открывает «Оргструктуру», создаёт должности и указывает каждому сотруднику непосредственного руководителя в выбранной рабочей области. Должности описывают структуру и не заменяют существующие роли доступа. Циклы, назначение самого себя руководителем и связи с водителями, внешними рекрутерами или чужой областью запрещены.

Задача содержит название, описание, исполнителя и необязательный срок. Руководитель может назначать задачи любому подчинённому по всей цепочке, администратор — сотрудникам своей области. Канбан: «Выполнить» → «В процессе» → «Сделано». При назначении создаётся обычное личное сообщение с упоминанием исполнителя и кнопкой перехода к задаче. Задача и сообщение фиксируются одной транзакцией: повтор запроса не создаёт дублей. Доступ к карточке, редактированию и смене статуса проверяется на сервере по актуальной оргструктуре. Назначение также соблюдает антиконфликтный режим соответствующего личного чата.

## Итоги и благодарности

Обязанность сдавать итоги появляется у сотрудников с подчинёнными в оргструктуре. Недельная форма доступна с понедельника и должна быть сдана до конца пятницы; месячная — до конца последнего дня месяца. Время — Europe/Moscow. Поля: сделанное, работа в процессе, блокеры и необязательные благодарности коллегам. Месячная форма дополнительно требует фокус следующего месяца. Отсутствие результатов или блокеров можно указать явно текстом «нет».

Черновик доступен только автору. Администратор и вышестоящие руководители видят список обязательств, несданные и просроченные формы, а после сдачи — содержание. Просроченную форму можно сдать с отметкой об опоздании. Сданная форма сохраняется в истории без редактирования. Благодарности с причиной начисляются только после сдачи, один раз на получателя в отчёте; самоблагодарность запрещена. Получатель получает корону рядом с именем в чатах и счётчик благодарностей.

Сервер создаёт обязательства периодически, независимо от открытия вкладки. Снимки уже назначенных обязательств не исчезают после изменения оргструктуры. Учёт начинается с установки функции; прошлые обязательства до включения не создаются. Пока сервер полностью выключен, неизвестную историческую оргструктуру нельзя реконструировать: новые снимки создаются после запуска, существующие остаются в базе.

Изменения схемы: `050_team_read_notifications.sql`, `051_team_organization_tasks.sql`, `052_user_profiles.sql`, `053_team_outcomes.sql`. Проверки: `npm run test:team:social`, `npm run test:team:social:browser`, `npm run test:team:tasks:browser`, `npm run test:team:outcomes:browser`.

## Единое общение компании

В чатах нет обязательного выбора проекта. Сервер определяет компании сотрудника по его актуальным полномочиям и собирает открытые каналы из всех проектов этих компаний. Переписка, вложения, членство, исходные идентификаторы и история операций остаются на прежних местах: перенос данных и миграция схемы не нужны. Старые закрытые каналы и личные диалоги не становятся публичными.

`GET /team/context` возвращает `companyMode`, `scopes` всех проектов компаний, `defaultResponsibilityScopeId` и `workScopes` исходных полномочий. `GET /team/conversations`, `/people`, `/unread`, `/mentions`, `/profile-directory` и карточки `/profiles/:id` работают без выбора области. Диалоги, уведомления и упоминания содержат исходный `responsibilityScopeId`; запросы истории, отправки, изменений и скачивания используют его. Справочник участников содержит `responsibilityScopeIds` для переписки и `workResponsibilityScopeIds` для прежних проектных функций. Упоминания `@all` открытого канала включают действующих сотрудников его компании, а закрытого — только действующих участников.

База знаний, оргструктура, задачи, результаты, сводки и расписания сохраняют исходные права по проектам. Список статей без фильтра объединяет только доступные по исходным полномочиям материалы и сохраняет идентификатор проекта каждой статьи; дополнительные права редактирования также проверяются в исходном проекте. Выбор получателей сводок остаётся явным и сохраняет прежние ограничения. Права других модулей приложения не расширяются.

Проверка нового контракта: `node --test tests/team-company-integration.test.cjs` из корня проекта. Она создаёт временную PostgreSQL и проверяет сотрудников с непересекающимися проектами, чужую компанию, административное управление видимостью, исключение создателя, вложения, уведомления, личные диалоги и отзыв полномочий.

## Ежедневные отчёты выпуска

Администратор открывает «Расписание» и выбирает «Ежедневный выпуск транспорта». В существующем чате «Отчеты» также есть переход к настройке. Данные экипажного блока и городской доставки автоматически собираются из «Планирования»: выбирать рабочие области не требуется. Настраиваются время, часовой пояс и текущий/предыдущий день; при нескольких доступных чатах можно выбрать назначение. Для этой установки используется 18:00 Europe/Moscow, текущий день. Перед публикацией доступен предпросмотр даты; сообщение можно обновить вручную.

Повторный запуск и вечернее расписание обновляют одно обычное сообщение за дату в выбранном чате. Отдельного реестра отчётов или второго канала не создаётся. При отсутствии канала может быть создан один обычный публичный «Отчеты» в выбранной компании; существующий явно выбранный канал всегда переиспользуется. Удалённые сообщения и архивные/закрытые/удалённые каналы не восстанавливаются автоматически.

Данные берутся из существующих дневных планов и отметок оперативных рейсов. Уникальные машины, фактические и дополнительные рейсы, собственный/наёмный парк, экипажная/городская доставка и причины невыпуска считаются отдельно. Неизвестные сведения и неполные планы явно обозначаются. Разрезы городов, клиентов и ответственных доступны внутри каждого блока. В общем чате менеджеры обозначены обезличенными устойчивыми метками; разрешённые имена доступны администратору в отдельной таблице предпросмотра. Комментарии, документы, телефоны и имена водителей в публикацию не входят.

Источники определяются заново при каждом запуске: используются существующие области с планами, рейсами или активным каталогом машин, доступные владельцу по исходным полномочиям с `personal_data_visible`. Рабочие области без данных планирования не создают ложных предупреждений о недостающих планах. Новые доступные данные подхватываются автоматически; отозванные полномочия исключают источник. Расширенный список проектов общения компании не даёт права чтения планов. Существующий доступный публичный чат может объединять операционные данные разных технических компаний; без явного чата сохраняется ограничение его компанией. Права владельца и канала проверяются при каждом запуске. Отсутствие доступа ко всему планированию и удаление/закрытие канала останавливают публикацию с видимой причиной; прочие ошибки имеют ограниченные повторные попытки. После перезапуска планировщик продолжает сохранённое расписание. Для своевременной отправки сервер приложения должен работать.

Используется существующий `team_summary_schedules` с `report_kind='fleet_release'`, `source_scope_ids`, `report_day_offset`, `target_conversation_id` и существующий журнал запусков с `message_id`. Пустой `source_scope_ids` означает автоматический сбор; фиксированный непустой список старого API сохраняет прежние строгие проверки каждого источника. Миграция `072_fleet_report_automatic_sources.sql` расширяет только существующее ограничение, новых сущностей не создаёт. Извлечение саммари переписки продолжает работать отдельно с `report_kind='conversation_summary'`. Миграция `069_fleet_daily_reports.sql` также сохраняет требование сборки оригиналов сообщения/канала в одной транзакции при выполнении публикации внутри savepoint.

API: `GET /team/fleet-reports` — предпросмотр; `POST /team/fleet-reports` — публикация; `GET /team/schedules?reportKind=fleet_release` и `PUT /team/schedules` — расписание. Параметры отчёта: `responsibilityScopeId` области чата, `businessDate`, необязательный явный `conversationId`. Интерфейс не передаёт `sourceScopeIds`; отсутствие поля или пустой массив в POST означает автоматический сбор. Старый API поддерживает непустой список через запятую в GET или массивом в POST. Методы доступны администратору; они не изменяют права чтения остальных чатов. Аудит публикации сохраняет фактически использованные источники.

Проверки из `recovered`: `npm run test:fleet:daily`, `npm run test:fleet:daily:browser`. Браузерные проверки поддерживают `PLAYWRIGHT_MODULE`, `CHROME_PATH`, `PLANNING_BUILT_FRONTEND=true`.
