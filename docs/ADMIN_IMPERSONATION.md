# Вход администратора в учётную запись сотрудника

В разделе «Сотрудники» нажмите «Войти как сотрудник» в карточке нужного пользователя. Откроется его учётная запись с его ролью, правами и доступными данными. Пароль сотрудника для этого не требуется.

Во время такого входа сверху отображаются текущий сотрудник и кнопка «Вернуться в админку». Она завершает временную сессию и возвращает администратора. Обновление страницы сохраняет режим. Временная сессия действует до 30 минут и не дольше исходной сессии администратора.

Доступ разрешён активному подтверждённому администратору доступа (`access_admin`) для активных подтверждённых сотрудников, все области и признаки доступа которых входят в его полномочия. Учитываются также доступ к финансовым и персональным данным. Для собственной карточки, заблокированного пользователя и пользователя вне полномочий кнопка недоступна. Повторный переход в другую учётную запись из этого режима запрещён.

Из временной сессии нельзя создавать сотрудников, менять пароли, отзывать доступ и привязывать аккаунт MAX. Обычные действия сотрудника выполняются с его правами. В журнале аудита вход, выход и действия содержат сведения об исходном администраторе. Пароли и токены в журнал не записываются.

Если исходная сессия администратора истекла или отозвана, его учётная запись отключена, пароль сброшен либо полномочия изменились, временная сессия прекращает работать. При завершении временного входа сохранённое устройство администратора остаётся доступным; устройство сотрудника не запоминается.

## Проверки и установка

HTTP-проверки используют отдельный временный PostgreSQL и синтетические учётные записи:

```sh
cd recovered
node --test ../tests/admin-impersonation-integration.test.cjs
npm run test:impersonation:browser
```

Для браузерной проверки нужны Playwright и Chromium. При необходимости задайте `PLAYWRIGHT_MODULE` и `CHROME_PATH`; `IMPERSONATION_BUILT_FRONTEND=true` проверяет собранный интерфейс.

Установка требует миграции `024_admin_impersonation.sql` и обновления API и интерфейса. Скрипт `recovered/infra/deploy/apply-impersonation.py` проверяет свежие контрольные суммы сервера, сохраняет базу и предыдущие файлы, применяет добавочную миграцию и проверяет готовность. При ошибке запуска возвращается предыдущая сборка; бизнес-данные из резервной копии автоматически не восстанавливаются.
