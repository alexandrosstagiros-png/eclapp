# Разработка

Раздел для обратной связи сотрудников по приложению. Одна карточка тикета проходит две воронки без копирования и потери обсуждения.

| Воронка | Этапы |
| --- | --- |
| Аналитика | Новые → Уточнение → Готово к разработке |
| Продакшен | В работе → Проверка → Готово |

«Продакшен» здесь обозначает очередь реализации. Перемещение тикета само по себе не меняет код и не публикует приложение.

## Работа с тикетом

1. Откройте «Разработка» и выберите область работы, если доступно несколько.
2. Нажмите «Новый тикет», укажите название, раздел приложения и описание проблемы или пожелания. Полезно написать, что делали, что получилось и какой результат нужен.
3. Новое обращение попадает в «Аналитика → Новые». Уточнения добавляются комментариями в карточке.
4. Администратор перемещает карточку по этапам. После аналитики та же карточка переходит в «Продакшен → В работе», затем в «Проверка» и «Готово».
5. При необходимости администратор возвращает тикет на предыдущий этап. Все изменения этапов и комментарии сохраняются в истории.

Доступны поиск и две доски по три колонки. Отдельных проектов разработки, спринтов, типов задач и справочников приоритетов нет. Вложения и автоматические внешние уведомления в этот релиз не входят.

## Доступ

Штатные роли могут создавать тикеты в своих областях, просматривать и редактировать собственные обращения, добавлять комментарии. Администратор доступа видит обращения сотрудников в своих областях и управляет этапами. Внешним рекрутерам раздел недоступен. Новая роль программиста и дополнительные административные права этим изменением не выдаются.

Сервер повторно проверяет сессию и полную область доступа при чтении и записи. Имена других сотрудников маскируются при отсутствии разрешения на персональные данные. Автор назначается сервером. Конфликт версий не перезаписывает чужие изменения; интерфейс сохраняет введённый текст и предлагает загрузить актуальную карточку.

## Техническая часть

- Миграция: `040_development.sql`; таблицы `development_tickets` и `development_events`.
- API: `GET /development/context`, `GET /development`, `GET /development/tickets/:id`, `PUT /development/tickets`, `POST /development/comments`.
- Интерфейс: `recovered/apps/office-web/src/development.js`; прямая ссылка `?section=development`.
- Проверки из `recovered`: `npm run test:development`, `npm run test:development:browser`, `npm run build`.
- Браузерная проверка использует отдельную временную PostgreSQL и синтетические аккаунты. Для готовой сборки: `DEVELOPMENT_BUILT_FRONTEND=true npm run test:development:browser`.

Максимум одного просмотра — 2 000 доступных тикетов в области. При превышении сервер возвращает явное сообщение; скрытого усечения списка нет.
