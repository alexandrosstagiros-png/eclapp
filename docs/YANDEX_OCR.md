# Yandex OCR для оформления кандидатов

По умолчанию используется [VK Cloud](VK_OCR.md). Этот документ описывает дополнительный адаптер `recovered/apps/api/src/modules/recruitment/yandex-ocr.js`, который включается только через `ONBOARDING_OCR_PROVIDER=yandex`. Он отправляет изображение из серверного буфера в синхронный Yandex Vision OCR. Он не сохраняет файлы, не пишет содержимое запросов/ответов в логи, не подтверждает подлинность документа и не отмечает карточку проверенной. Полученные текст и поля — черновик для сверки рекрутером. Жизненный цикл фотографий и права доступа реализует сервис оформления.

## Настройка сервера

Передайте API-процессу две переменные через используемое защищённое хранилище секретов:

```dotenv
ONBOARDING_OCR_PROVIDER=yandex
YANDEX_OCR_API_KEY=<API-ключ сервисного аккаунта>
YANDEX_OCR_FOLDER_ID=<идентификатор каталога>
```

Не помещайте ключ в репозиторий, браузерный `.env`, поле конструктора или клиентский запрос. Перезапустите API после обновления окружения. По [официальной инструкции](https://aistudio.yandex.ru/ru/docs/vision/operations/ocr/text-detection-image) нужны роль сервисного аккаунта `ai.vision.user` и область API-ключа `yc.ai.foundationModels.execute`; в каталоге должна быть доступна оплата сервиса. Отсутствие настройки оставляет возможность ручного заполнения.

`getOcrStatus()` возвращает только `{ configured, provider, maxBytes, supportedMimeTypes, documentTypes }`. `configured` подтверждает наличие корректно заданных переменных, а не работоспособность ключа или положительный баланс. Проверка этого статуса не обращается к Яндексу и не тарифицируется.

## Контракт

```js
const { recognizeDocument, getOcrStatus } = require('./onboarding-ocr');
const result = await recognizeDocument({
  buffer, // Buffer, JPEG или PNG, не более 10 * 1024 * 1024 байт
  mimeType: 'image/jpeg',
  documentType: 'passport',
});
// { text: '...', fields: { surname: '...', number: '...' }, model: 'passport' }
```

Имена полей сохраняются как у провайдера. Даты и номера не преобразуются автоматически; это предотвращает потерю ведущих нулей и неверную интерпретацию дат. Поля от неизвестных моделей/сущностей отбрасываются. Для моделей `page` возвращается текст, `fields` остаётся пустым.

| Тип документа в приложении | Модель Яндекса |
| --- | --- |
| `passport` — основной разворот целиком | `passport` |
| `passport_registration` | `page` |
| `driver_license_front` | `driver-license-front` |
| `driver_license_back` | `driver-license-back` |
| `vehicle_registration_front` | `vehicle-registration-front` |
| `vehicle_registration_back` | `vehicle-registration-back` |
| `snils`, `other` | `page` |

Модели и поля сверены с [перечнем Яндекса](https://aistudio.yandex.ru/ru/docs/vision/concepts/ocr/models) 26 сентября 2026 года. Отдельной шаблонной модели для СНИЛС и страницы регистрации здесь нет; заполнять эти данные следует по распознанному тексту вручную.

## Сетевой запрос и ограничения

Используется фиксированный endpoint `https://ai.api.cloud.yandex.net/ocr/v1/recognizeText` из текущей [пошаговой инструкции](https://aistudio.yandex.ru/ru/docs/vision/operations/ocr/text-detection-image). [REST-справочник](https://aistudio.yandex.ru/ru/docs/vision/ocr/api-ref/TextRecognition/recognize) также описывает адрес `ocr.api.cloud.yandex.net` и невложенный ответ; адаптер понимает обе документированные формы ответа, но отправляет запрос только на один фиксированный адрес. Переадресации запрещены. Тело содержит Base64, `mimeType`, `languageCodes: ["*"]` и модель, а заголовки — `Authorization: Api-Key …`, `x-folder-id` и `x-data-logging-enabled: false`.

Тайм-аут — 20 секунд, включая чтение ответа. Автоматических повторных платных запросов нет. Разрешены JPEG/PNG с проверкой сигнатуры, до 10 МиБ. Яндекс дополнительно ограничивает изображение 20 мегапикселями: камера/форма должна уменьшать слишком большие снимки до отправки. Ответ ограничен 2 МиБ. Ошибки содержат только заранее написанное сообщение на русском и код `ONBOARDING_OCR_*`; тело ошибки Яндекса не читается и пользователю не передаётся. Внешний HTTP-контроллер не должен принимать внутренние `options.fetchImpl`/`options.timeoutMs` из запроса.

## Хранение и проверка

Заголовок отключает использование содержимого запросов для улучшения сервиса согласно [инструкции по логированию](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/disable-logging). Здесь используется синхронный API: операция асинхронного распознавания не создаётся. Указанное Яндексом хранение результатов асинхронного OCR три суток не является механизмом удаления фотографий в нашем приложении; это отдельное правило [политики хранения провайдера](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/security/data-storage). Удаление локального оригинала не удаляет распознанные поля карточки.

При эксплуатации запретите запись тел OCR-запросов в HTTP/APM/proxy-логи и исключите временные фотографии из долгоживущих резервных копий. Сохраняйте в журнале действий только идентификатор операции, автора, время и результат. Доступ к фото и распознанным данным должен проверять сервис оформления до вызова адаптера.

Тесты не используют реальные документы и не обращаются к платному API:

```sh
node --test tests/onboarding-ocr.test.cjs
```

Они проверяют параметры запросов, защиту ключа и отключение логирования, типы моделей, фильтрацию полей, отбрасывание некорректных файлов и ответов, отсутствие повторных вызовов, тайм-аут подключения и чтения, безопасные сообщения об ошибках. Для запуска в рабочем окружении отдельно нужен небольшой проверочный запрос на синтетическом изображении после настройки ключа; он намеренно не выполняется тестами.
