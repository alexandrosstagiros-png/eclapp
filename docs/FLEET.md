# Автопарк в ЕЦЛ

Раздел «Автопарк» объединяет историю обслуживания из XLSX/CSV и текущую работу: автомобили, заказ-наряды, ТО, запчасти, склады, закупки, заправки, назначения и заявки водителей. Аналитика и скачиваемая презентация используют один расчёт. Импортированная история доступна в «Позициях», новые документы создаются в «Заказ-нарядах».

Локальная установка проверена 24 сентября 2026: `http://127.0.0.1:18514/?section=fleet`, область «Автопарк · Обслуживание». Исходная книга активирована, созданы 141 карточка по номерам без догадок о VIN. Принадлежность юридическому лицу не установлена из книги; область импорта обозначена отдельно. Перед миграциями сохранена остановленная база в `.local/backups/fleet-cold-2026-09-24T07-59-41-374Z`. Проверка установки и контрольные суммы — `.local/fleet-maintenance/live-verification.json`. На удалённый сервер эта версия не публиковалась.

## Начало работы

1. Выберите область работы. Сотруднику нужен доступ к этой области с видимостью финансов; доступны администратор, менеджер, механик и аудитор. Аудитор просматривает данные и скачивает отчёты.
2. В импорте загрузите книгу или CSV, проверьте число строк, сумму, диагностику и активируйте снимок. Новый снимок **заменяет активную импортированную историю**; прежние версии остаются в истории. Живые документы ЕЦЛ сохраняются. Повтор того же файла не создаёт дублей. CSV с собственными документами `app:` нельзя импортировать обратно как внешнюю историю.
3. В автомобилях нажмите «Из загруженной истории». Это создаёт карточки по номерам; предполагаемые замены номеров автоматически не объединяются. VIN, подтверждённую принадлежность и группы уточняют сотрудники.
4. Создайте склады, номенклатуру и поставщиков. Начальные остатки вводите только по фактической инвентаризации: количество, стоимость единицы и основание. Расходы старых ремонтов не являются складским остатком.
5. Создайте закупку, затем «Заказать» → «Принять на склад». Приёмка проводится однократно. Создайте ремонт, внесите работы и детали, затем завершите. Складские детали списываются атомарно по средней стоимости; при нехватке остатка весь документ остаётся непроведённым.
6. Для ТО укажите дату/пробег либо интервал и последнее выполнение. Создайте связанный заказ-наряд из плана ТО. Его завершение обновляет дату/пробег последнего ТО и следующий срок.
7. В «Водителях» назначьте сотруднику автомобиль. В его кабинете «Мой автомобиль» доступны сообщения о неисправностях, заправках и пробеге. Подтвердите заявку в «Заявках водителей»; заправка попадёт в топливо, неисправность можно связать с ремонтом.

## Аналитика и презентация

Укажите период и основу даты (открытие или завершение), статус, автомобиль, группу/узел затрат, тип позиции, поставщика и другие отборы. KPI рассчитываются по **всем** подходящим строкам; страницы ограничивают только отображение деталей. Переход из агрегата сохраняет соответствующий отбор. CSV выгружает всю выборку. «Скачать презентацию» формирует PPTX с редактируемыми диаграммами/таблицами, выбранными фильтрами, источником, помесячной динамикой, структурой расходов, дорогими автомобилями и диагностикой данных.

В презентации топливо и ТО при наличии показаны отдельными разделами по всей области с явным обозначением охвата. Закупки и топливо не добавляются к расходам ремонта. Отчёт не придумывает расход л/100 км при отсутствии достаточных измерений. Документы, созданные в ЕЦЛ, учитываются вместе с импортом; при фильтре по дате завершения незавершённые новые ремонты не попадают в период.

Исходные суммы импортированных строк сохраняются, включая скидки, отрицательные корректировки и возможные повторы. Пропущенный поставщик не означает ремонт своими силами. Диагностика показывает спорные строки, но не удаляет их. Связь сменившихся номеров подтверждается отдельно с основанием. Историческая сверка из книги имеет собственный неполный охват и не выдаётся за полную сверку с 1С.

Контроль исходной книги `Заказ-наряды_автопарк v3.xlsx`: 35 643 позиции, 4 408 заказ-нарядов, 141 номер, 92 103 357,26 ₽. Июль 2026 по завершению: 2 319 позиций, 302 заказ-наряда, 111 номеров, 6 246 936,14 ₽. Excel-формулы и старые диапазоны сводных таблиц не используются для вычисления итогов.

## Границы текущей версии

Это собственный рабочий модуль в ЕЦЛ. Внешние интеграции Завгара, телематика, топливные карты, ЭДО и автоматическая синхронизация складов не подключены. Чеки можно указать номером; вложения чеков не реализованы. Частичные приёмки, возвраты, межскладские перемещения и обратное проведение закрытых документов требуют отдельного процесса и пока отсутствуют. Проведённые ремонты/закупки и принятые топливные заявки защищены от переписывания. Для исторических заказ-нарядов исправления делаются в источнике с новым проверенным снимком; ЕЦЛ не изменяет исходный Excel.

## Техническая проверка

Миграции: `034_fleet_maintenance.sql`, `035_fleet_operations.sql`. Данные привязаны к полной области юридического лица, региона, проекта и ответственности. Версии записей защищают от перезаписи параллельных изменений, журнал и складские движения сохраняются отдельно. Сессии и права повторно проверяются на сервере.

Из `recovered`: `npm run test:fleet`, `npm run test:fleet:browser`, `npm run build`. Для контрольного теста книги задайте `FLEET_SOURCE_XLSX` абсолютным путём. Браузерные тесты используют только временную PostgreSQL и синтетические данные; поддерживают `PLAYWRIGHT_MODULE`, `CHROME_PATH`, `FLEET_BUILT_FRONTEND=true`. Ограничения импорта: файл 20 МиБ, распаковка XLSX 160 МиБ, 100 000 аналитических строк. Превышение выдаёт ошибку вместо скрытого усечения.
