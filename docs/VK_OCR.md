# VK Cloud Vision для оформления

Провайдер по умолчанию — **VK Cloud Vision**. Серверный контракт остался прежним: `recognizeDocument({buffer,mimeType,documentType})` возвращает `{text,fields,model}`. Фотографии отправляются только выбранному провайдеру; автоматического переключения на Яндекс при ошибке нет. Реальные платные вызовы при разработке не выполнялись.

## Подключение

В проекте VK Cloud откройте **AI API → Vision API → Добавить сервисный токен**, выберите задачи распознавания текста и полей документов. Передайте токен серверу через хранилище секретов:

```dotenv
ONBOARDING_OCR_PROVIDER=vk
VK_OCR_TOKEN=<сервисный токен Vision API>
```

`ONBOARDING_OCR_PROVIDER=vk` можно опустить: это значение по умолчанию. Яндекс используется только при явно заданном `ONBOARDING_OCR_PROVIDER=yandex`; его отдельная настройка описана в [YANDEX_OCR.md](YANDEX_OCR.md). Наличие старых переменных Яндекса не включает отправку в Яндекс.

VK документирует сервисный токен без ограничения срока действия и OAuth-токены со сроком действия один час. Текущая интеграция рассчитана на сервисный токен; автоматического OAuth refresh нет. Не вставляйте секрет в форму, браузерный код, репозиторий или сообщения. `getOcrStatus().configured` показывает наличие токена, но не проверяет доступность сервиса и баланс. Источник: [официальная авторизация Vision](https://github.com/vk-cs/docs-public/blob/master/docs/ru/ml/vision/quick-start/auth-vision/auth-vision.md).

## Что распознаётся

| Документ | Вызов | Результат |
| --- | --- | --- |
| Основной разворот паспорта | `/api/v1/docs/recognize` | Поля паспорта и текстовое представление этих полей |
| Регистрация, обе стороны ВУ/СТС, СНИЛС, другой документ | `/api/v1/text/recognize` | Распознанный текст; перенос в поля вручную |

Для паспорта официальный ответ `labels` преобразуется в совместимые ключи конструктора: `first_name → name`, `last_name → surname`, `birthday → birth_date`, `birthplace → birth_place`, `date_of_issue → issue_date`, `place_of_issue → issued_by`, `code_of_issue → subdivision`, `sex → gender`, `middle_name → middle_name`. `series` и `document_number` сохраняются отдельно, а `number` содержит серию и номер вместе. Числа и даты остаются строками. Текст ответа паспорта составляется из полученных полей; это не отдельный второй OCR-запрос. Источник: [распознавание полей документов](https://github.com/vk-cs/docs-public/blob/master/docs/ru/ml/vision/instructions/docs-recognition/docs-recognition.md).

Публичная документация подтверждает извлечение полей на примере паспорта. Автоматический разбор полей ВУ, СТС и СНИЛС здесь не обещается. Для них `fields` пуст, `model` равен `vk-text`; для паспорта — `vk-docs`. Рекрутер сверяет результат с фотографией. Источник: [распознавание текста](https://github.com/vk-cs/docs-public/blob/master/docs/ru/ml/vision/instructions/vision-api-txt/vision-api-txt.md).

## Запрос и защита

Используется фиксированный HTTPS-хост `smarty.mail.ru` и только два указанных выше пути. По документации VK токен передаётся в query `oauth_token`, провайдер — `oauth_provider=mcs`. Изображение отправляется как multipart `file`; поле `meta` содержит `{"images":[{"name":"file"}]}`. URL с токеном никогда не возвращается браузеру и не записывается адаптером в лог. Отключите запись исходящих URL/query и тел в APM/proxy; не включайте debug-логирование HTTP-клиента.

Запрещены переадресации и автоматические повторные платные вызовы. Тайм-аут 20 секунд охватывает подключение и чтение ответа. Принимаются JPEG/PNG до 10 МиБ (лимит приложения), с проверкой заголовка и размеров: ширина 5–3840, высота 5–2160 пикселей. Камера должна уменьшать снимок с сохранением пропорций. VK документирует до 15 МБ на изображение и максимум 4K; наше приложение сохраняет более строгий лимит размера файла. Ответ ограничен 2 МиБ. Ошибки заменяются безопасными сообщениями на русском, без исходного URL и текста ошибки провайдера. Источник: [ограничения Vision](https://github.com/vk-cs/docs-public/blob/master/docs/ru/ml/vision/concepts/vision-limits/vision-limits.md).

## Стоимость для 250–300 оформлений

В официальной публичной документации VK Cloud при объёме до 1 000 000 изображений в месяц указано **0,06 ₽ за изображение**. Последнее изменение страницы тарифа — 19 июня 2026 года; проверено 26 сентября 2026 года. Источник: [тарификация Vision](https://github.com/vk-cs/docs-public/blob/master/docs/ru/ml/vision/tariffication/tariffication.md).

| Оформлений | Изображений, по 7 на человека | Распознавание |
| --- | ---: | ---: |
| 250 | 1 750 | 105 ₽/месяц |
| 300 | 2 100 | 126 ₽/месяц |
| Запас 20% на повторные снимки | 2 100–2 520 | 126–151,20 ₽/месяц |

Это арифметический расчёт по публичному тарифу: один вызов одного метода на изображение. Хранение, сервер приложения и другие услуги не включены. На странице не указано, включён ли НДС; финальный налоговый режим и договорный тариф нужно сверить в проекте VK Cloud. Повторное распознавание того же снимка увеличивает расход.

## Персональные данные и сроки

Удаление через 72 часа реализуется **в нашем приложении**. Это не гарантия такого же срока у VK. В общих [вопросах безопасности VK Cloud](https://github.com/vk-cs/docs-public/blob/master/docs/ru/intro/it-security/faq/faq.md) указан срок удаления временных файлов и документов до одного месяца. Отдельный срок для Vision, API удаления обработанных изображений и аналог заголовка Яндекса для отключения содержимого логов в изученной документации не описаны. Неподдерживаемый заголовок Яндекса в VK не отправляется и ничего не обещает.

Официальная [страница соответствия 152-ФЗ](https://github.com/vk-cs/docs-public/blob/master/docs/ru/intro/it-security/compliance-152fz/compliance-152fz.md) описывает российское размещение данных, аттестованную инфраструктуру и отдельный сервис «Облако 152-ФЗ» с разделением ответственности. Это не заменяет подтверждение условий именно Vision для вашего проекта. При вводе в эксплуатацию уточните у VK условия обработки паспортов, срок удаления входных изображений/результатов, резервных копий и логирования. Фотографии в нашем spool должны находиться вне резервных копий приложения; распознанные поля карточки имеют отдельный жизненный цикл.

## Проверка без платного API

```sh
node --test tests/vk-ocr.test.cjs tests/onboarding-ocr.test.cjs
```

Проверяются выбор провайдера без fallback, точный multipart-контракт VK, безопасная обработка токена, поля паспорта, режим обычного текста, ограничения изображений/ответов и тайм-ауты. Все ответы подменяются локальными функциями; для эксплуатационной проверки после настройки нужен отдельный запрос на синтетическом изображении.
