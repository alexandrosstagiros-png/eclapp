# Договоры в оформлении кандидатов

Для массового оформления документов одной кнопкой см. [Комплекты оформления: ТК и перевозчики](RECRUITMENT_DOCUMENT_PACKS.md). Этот режим дополнительно использует 37 шаблонов из двух новых Excel-файлов и автозаполнение реквизитов через DaData.

Договоры находятся в разделе **Оформление** в левом меню сразу под «Рекрутингом». Анкета, договор и подписанный файл связаны с одним кандидатом. Создание договора не переводит кандидата на следующий этап подбора и не подтверждает выход на работу.

## Работа с договором

1. В подразделе «Договоры» создайте договор по опубликованному шаблону. Выберите кандидата или его анкету оформления. Из анкеты переносятся значения полей с совпадающими идентификаторами; перед выдачей их нужно сверить.
2. Заполните номер, дату и реквизиты. Черновик допускает изменение текста и значений полей. Сохраните его и проверьте предварительный просмотр.
3. После проверки выдайте договор. Приложение зафиксирует текст, заполненные реквизиты и версию шаблона. Выданный договор нельзя незаметно переписать; для нового документа создайте новый черновик.
4. Распечатайте договор или сохраните PDF через диалог печати браузера. Доступно также скачивание документа в HTML.
5. После подписания приложите подписанный PDF, JPEG или PNG и укажите дату подписания. Это регистрация полученного файла, а не электронное подписание документа.

Подписанные файлы хранятся постоянно вместе с данными договора. Правило удаления фотографий анкеты через 72 часа на них не распространяется.

## Конструктор шаблонов договоров

Руководитель или администратор с доступом к персональным данным может создавать и редактировать шаблоны. Рекрутер использует опубликованные версии для своих договоров, а также может редактировать и публиковать собственные шаблоны, восстановленные из договоров.

Шаблон содержит название, тип оформления (в том числе «Любой тип оформления»), текст и поля. Место подстановки обозначается `{{идентификатор_поля}}`, например `{{full_name}}`. Номер и дата договора подставляются через `{{contract_number}}` и `{{contract_date}}`. Для поля можно задать название, тип, обязательность и значение по умолчанию. Для срока действия можно включить ограничение «Не раньше даты документа». Реквизиты организации и подписанта задаются явно в шаблоне или его полях. Типизированные даты печатаются в формате `ДД.ММ.ГГГГ`.

Сохранение черновика и публикация — разные действия. Пока новая редакция не опубликована, новые договоры используют предыдущую опубликованную версию. Публикация сохраняет отдельную версию шаблона. Уже созданные договоры сохраняют свой снимок и не меняются при редактировании шаблона.

Начальный образец в конструкторе предназначен для заполнения своим согласованным текстом. Для локальной базы отдельно подготовлены два шаблона из файла «Оформление водителей.xlsx»: договор аренды транспортного средства с актом приёма-передачи и доверенность на передачу и получение ТС в сервисе. Формулы Excel заменены подстановками. Реквизиты организации и сумма аренды заданы как редактируемые значения по умолчанию; сведения человека, автомобиля и срок действия заполняются для каждого документа. Эти шаблоны — данные локального приложения, они не встроены в исходный код или миграции.

## Удаление и восстановление

В списках договоров и шаблонов есть переключатель «Действующие / Корзина». Удаление требует подтверждения и переносит запись в корзину. Из корзины можно вернуть ту же запись. История публикаций, текст выданного документа и оригинальный подписанный файл сохраняются; удаление шаблона не удаляет ранее созданные по нему договоры.

Рекрутер может удалять и восстанавливать доступные опубликованные шаблоны компании и свои договоры. Руководитель и администратор выполняют эти действия в пределах доступной компании. Диспетчер не получает право удаления и восстановления.

Кнопка «Восстановить шаблон» в карточке договора создаёт отдельный черновик из исходной версии шаблона, сохранённой в этом договоре. Она работает и после удаления исходного шаблона. Заполненные значения и персональные правки текста договора не переносятся в общий шаблон. Сначала проверьте полученный черновик, затем опубликуйте его. Если сам договор находится в корзине, сначала восстановите его.

## Доступ и сохранность

- Внутренний рекрутер и диспетчер видят свои договоры при наличии доступа к персональным данным. Руководитель и администратор — договоры своей компании.
- Внешние рекрутеры не получают доступ к этому разделу.
- Текст договора, значения полей и содержимое подписанных файлов не включаются в события аудита. В аудите сохраняются действия, идентификаторы и версии.
- Изменения проверяют версию записи: устаревшая вкладка не перезаписывает более свежие правки другого сотрудника.
- Анкеты, фотографии анкеты, проверка СБ и договоры сохраняют свои отдельные состояния. Договор не подменяет проверку анкеты или СБ.

## API

Все маршруты начинаются с `/api/v1/recruitment/contracts`, требуют действующей сессии сотрудника и возвращают `Cache-Control: no-store`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /context` | Метаданные доступных шаблонов и договоров, право на конструктор, признак усечения списка |
| `GET /templates/:id` | Черновик для редактора, текущая опубликованная версия и история публикаций |
| `PUT /templates` | Создать или обновить шаблон с проверкой `version`; `state: draft` сохраняет черновик, `state: published` публикует переданную редакцию |
| `POST /templates/:id/publish` | Опубликовать сохранённый черновик; тело `{version}` |
| `POST /templates/:id/delete` / `restore` | Перенести шаблон в корзину или вернуть его; тело `{version}` |
| `POST /documents` | Создать договор: `{templateId,candidateId?,onboardingSessionId?}`; для копии — только `{sourceDocumentId}` |
| `GET /documents/:id` | Договор, его снимок шаблона, значения и текст предпросмотра |
| `PUT /documents/:id` | Сохранить черновик: `{version,text,values,number,date}` |
| `POST /documents/:id/issue` | Проверить обязательные поля и зафиксировать договор; тело `{version}` |
| `POST /documents/:id/sign` | Добавить подписанный файл: `{version,signedDate,mimeType,base64,fileName}` |
| `POST /documents/:id/delete` / `restore` | Перенести договор в корзину или вернуть его; тело `{version}` |
| `POST /documents/:id/restore-template` | Новый черновик исходного шаблона без заполненных значений; тело `{version,name?}` |
| `GET /documents/:id/signed-file` | Скачать оригинальные байты подписанного файла после проверки доступа |

Шаблон: `{id,version,responsibilityScopeId,name,employmentType,text,fields,state}`. Тип оформления: `employee`, `ip`, `self_employed` или `any` (последний допустим только для договорных шаблонов, не анкет). Поле: `{id,label,type,required,defaultValue?,notBeforeContractDate?}`, тип — `text`, `textarea`, `date` или `tel`. Идентификатор поля начинается с латинской буквы и содержит латинские буквы, цифры, `_` или `-`. Неизвестные и некорректные подстановки отклоняются. Текст обрабатывается как обычный текст, а не HTML.

`GET /context?deleted=true` возвращает корзину; для просмотра удалённой карточки добавьте тот же параметр к `GET /templates/:id` или `GET /documents/:id`. Без параметра выдаются активные записи. В ответах есть `deletedAt`, `deletedBy` и флаги доступных действий. Скачивание подписанного файла, копирование и восстановление шаблона доступны после возвращения договора из корзины.

Даты API — календарные строки `YYYY-MM-DD`. Подписанный файл ограничен 10 МиБ; сервер проверяет допустимый формат и сигнатуру содержимого. Байты сохраняются в приватной таблице PostgreSQL и входят в резервную копию БД. Публикации шаблонов и подписанные файлы недоступны для перезаписи прикладной роли БД; дополнительный триггер запрещает изменение выданного текста договора.

Контекст ограничен последними 1000 шаблонами и 1000 договорами и сообщает `truncated`, если выборка усечена. История публикаций доступна в карточке шаблона. Проверка анкеты и этап подбора выполняются существующими маршрутами рекрутинга и не изменяются этими операциями.

## Автоматическая проверка

Из каталога `recovered`:

```sh
npm run build
TZ=Europe/Moscow npm run test:recruitment:contracts
npm run test:recruitment:contracts:browser
```

Браузерному сценарию требуется Playwright и Chromium; пути можно передать через `PLAYWRIGHT_MODULE` и `CHROME_PATH`. Переменная `RECRUITMENT_BUILT_FRONTEND=true` включает проверку собранных файлов. Интеграционные тесты договоров также включены в `test:recruitment:onboarding`.
