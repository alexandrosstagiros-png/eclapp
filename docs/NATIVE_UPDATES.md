# Обновления приложений ЕЦЛ

Обновления клиентских приложений хранятся в GitHub Releases. Исходный адрес канала — `https://github.com/alexandrosstagiros-png/eclapp/releases/latest/download/latest.json`. Он начинает работать после публикации первого полноценного релиза. Само наличие нового коммита в GitHub обновление пользователю не отправляет: нужен новый тег и успешная сборка релиза.

| Платформа | Получение обновления | Применение |
| --- | --- | --- |
| macOS | Приложение скачивает обновление и проверяет подпись | Пользователь видит уведомление; установка и перезапуск выполняются в удобный момент |
| Windows x64 | То же, установщик NSIS скачивается приложением | Применение закрывает приложение и запускает установщик; Windows может запросить разрешение |
| Android arm64, APK из GitHub | Приложение скачивает подписанный APK | Android требует разрешить установку из этого источника и подтвердить системный установщик |
| iOS | Новая версия распространяется через App Store или TestFlight | Обновляет магазин; установка IPA из GitHub внутри приложения не поддерживается |

Автоматическое получение обновления не должно неожиданно прерывать работу. Интерфейс показывает, когда новая версия готова, и предлагает применить её. Изменения API, базы данных и интеграции с 1С развёртываются отдельно: клиентский установщик не заменяет сервер на Mac и не запускает миграции базы данных.

## Что подготовлено в репозитории

`native/update-channel.json` задаёт репозиторий релизов и способ распространения Android. Публичный ключ Tauri встроен в `native/src-tauri/tauri.conf.json`. Закрытый ключ хранится отдельно от исходников, локально в `.local/native-signing/updater.key`; этот путь игнорируется Git. Сделайте защищённую резервную копию ключа: его замена потребует отдельного перехода для уже установленных приложений.

Workflow `.github/workflows/native-release.yml` выполняет следующие действия:

1. Проверяет стабильный тег `vMAJOR.MINOR.PATCH`, публичную доступность репозитория релизов и наличие необходимых секретов.
2. Приводит версии Tauri, npm package/lock и Cargo package/lock к версии тега, не меняя версии зависимостей. Это происходит в рабочем каталоге CI, без коммитов от бота.
3. Собирает обязательные macOS universal и Windows x64. Android собирается при включённом `NATIVE_ANDROID_RELEASE_ENABLED`.
4. Подписывает обновления ключом Tauri. Подпись содержит версию; приложение отклоняет несоответствие версии или ключа. APK дополнительно подписывается постоянным Android keystore.
5. Только после успешных сборок создаёт черновик GitHub Release, загружает все файлы, `latest.json` и `SHA256SUMS.txt`, проверяет полноту загрузки и публикует релиз. До публикации новый манифест не попадает пользователям.

Если включённая Android-сборка завершится ошибкой, новый релиз не публикуется. При ошибке загрузки остаётся черновик: повторный запуск с тем же исходным коммитом может его дополнить. Опубликованные релизы workflow не перезаписывает; для исправления выпускается следующая версия. Не перемещайте опубликованные теги. В настройках GitHub также можно включить immutable releases.

Для `alexandrosstagiros-png/eclapp` включён публичный доступ, загружены ключ подписи Tauri и постоянный Android keystore в Actions secrets, включена переменная `NATIVE_ANDROID_RELEASE_ENABLED=true`. Успешность конкретного выпуска проверяется по его запуску Actions и опубликованному GitHub Release.

## Однократная настройка GitHub

В `Settings → Secrets and variables → Actions` добавьте secrets:

| Secret | Назначение |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | Полное содержимое закрытого ключа `.local/native-signing/updater.key`, соответствующего встроенному публичному ключу |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Пароль ключа, если он задан; иначе не требуется |
| `ANDROID_KEYSTORE_BASE64` | Base64 постоянного Android keystore |
| `ANDROID_KEYSTORE_PASSWORD` | Пароль keystore |
| `ANDROID_KEY_ALIAS` | Имя ключа в keystore |
| `ANDROID_KEY_PASSWORD` | Пароль Android ключа |

И repository variables:

| Variable | Значение |
| --- | --- |
| `NATIVE_ANDROID_RELEASE_ENABLED` | `true`, чтобы каждый релиз включал Android; требует всех Android secrets |
| `NATIVE_RELEASE_REPOSITORY` | Необязательно: `owner/repository` публичного репозитория с установщиками. По умолчанию используется `native/update-channel.json` |
| `NATIVE_IOS_STORE_URL` | Необязательно: реальная ссылка App Store или TestFlight после публикации iOS приложения |
| `NATIVE_IOS_VERSION` | Версия, действительно опубликованная по ссылке выше. Задаётся отдельно от desktop-версии |

Для выбранного распространения Android через GitHub после добавления keystore установите `NATIVE_ANDROID_RELEASE_ENABLED=true`: это рекомендуемая постоянная настройка ЕЦЛ. До настройки секрета Android job намеренно не включается и манифест не обещает Android-обновление.

Ссылка iOS закрепляется также внутри `native/update-channel.json` при сборке. `prepare-release.cjs` переносит туда `NATIVE_IOS_STORE_URL`, а workflow передаёт эту переменную сборкам. Для первой самостоятельной iOS-сборки укажите ту же ссылку в канале до сборки и публикации в App Store/TestFlight. Изменить только переменную публикуемого манифеста недостаточно: старое iOS-приложение с `iosUrl: null` не показывает недоступный ему канал. Этот workflow не собирает и не публикует iOS в магазин.

Для отдельного репозитория установщиков нужен secret `NATIVE_RELEASE_TOKEN` с разрешением `Contents: write` только на этот репозиторий. Исходники могут оставаться приватными. Для релизов в том же публичном репозитории используется штатный `GITHUB_TOKEN`; токены никогда не встраиваются в приложение. Workflow сам не меняет видимость репозитория.

Для установки Android поверх предыдущей версии нужны неизменные `ru.ecl.workspace`, ключ подписи Android и возрастающий `versionCode`. Формула — `major × 1 000 000 + minor × 1 000 + patch`; `minor` и `patch` не больше 999. Начиная с публичной версии 0.1.1 используется постоянный release keystore: локальная защищённая копия находится в `.local/native-signing/android-release.jks`, реквизиты — в `android-release-credentials.json` рядом с ним. Оба файла исключены из Git; храните их защищённую резервную копию. Предыдущий локальный тестовый APK 0.1.0 был подписан Android Debug ключом и несовместим с новым ключом для установки поверх него: если он установлен, нужен однократный переход. Не удаляйте приложение без сохранения нужных локальных черновиков.

Подпись обновления Tauri подтверждает подлинность скачанного файла и отличается от доверенной подписи операционной системы. Для распространения macOS без предупреждения Gatekeeper нужны Apple Developer ID и нотарификация: workflow поддерживает secrets `APPLE_CERTIFICATE` (base64 `.p12`), `APPLE_CERTIFICATE_PASSWORD`, `KEYCHAIN_PASSWORD`, `APPLE_SIGNING_IDENTITY`, `APPLE_ID`, `APPLE_PASSWORD` (app-specific), `APPLE_TEAM_ID`. Без них используется ad-hoc подпись. Для Windows доверенная Authenticode-подпись настраивается отдельно; текущий workflow создаёт подписанное обновление Tauri, но не обещает отсутствие SmartScreen.

## Выпуск новой версии

Сначала должны быть проверены и отправлены в GitHub все необходимые исходники, включая `native/`, используемый `recovered/` и workflow. После этого создайте новый стабильный тег на проверенном коммите, например:

```sh
git tag v0.2.0
git push origin v0.2.0
```

Это пример команды публикации, а не выполненное действие. Можно также запустить **Publish native updates** вручную, указав уже существующий тег. Для первого релиза выберите версию выше установленной в приложениях. Последующие релизы должны быть выше опубликованной `latest` версии. Автопроверка не ставит более старые версии.

Перед широкой раздачей выполните проверку полного пути на тестовых устройствах: установите предыдущую версию, опубликуйте следующую, дождитесь уведомления, примените обновление и проверьте новую версию и сохранность настроек. Старые установщики, собранные до добавления механизма обновлений, не могут обновить себя задним числом: на них нужна однократная установка версии с updater.

## Формат манифеста

В `latest.json` обязательны `version` и `platforms` с `darwin-aarch64`, `darwin-x86_64`, `windows-x86_64`. Обе архитектуры Mac получают один universal-архив. URL ведут на конкретный неизменяемый тег; `signature` содержит саму подпись, а не ссылку на `.sig`.

Дополнительное поле `mobile.android` содержит собственные `version`, `url`, `signature`, `sha256`. Оно появляется только при успешной сборке и подписи APK этого релиза. `mobile.ios` содержит независимо опубликованные `version` и `url`; desktop-релиз не объявляет несуществующее обновление iOS.

Тесты генерации манифеста, версий, обязательных артефактов и ограничений подписи запускаются командой `node --test native/tests/release.test.cjs`. Структура подписи проверяется перед публикацией; криптографическую проверку скачанного обновления выполняет клиент перед установкой.

Официальные источники: [Tauri Updater](https://v2.tauri.app/plugin/updater/), [Tauri macOS signing](https://v2.tauri.app/distribute/sign/macos/), [GitHub Releases API](https://docs.github.com/en/rest/releases/releases), [Android app signing](https://developer.android.com/studio/publish/app-signing), [Apple TestFlight](https://developer.apple.com/testflight/).
