# Раздел «Тендеры»: предложение по структуре

Это концепция рабочего раздела, а не описание внедрённой функциональности.
Цель — вести возможности и следующие действия в одном месте, получая отчёт автоматически.
Основание: файл «КЛИЕНТУРА общий 11.09.xlsx», лист «Лист2», строки 2–30: 29 исходных записей.

## Что является карточкой

- Заказчик — постоянная карточка компании с контактами и связанной историей.
- Возможность — конкретный тендер, прямые переговоры или расширение действующего проекта.
- Одна карточка канбана соответствует одной возможности, а не всей работе с компанией.
- У одного заказчика могут одновременно быть несколько возможностей по регионам или проектам.
- Необязательное поле «Тип возможности»: «Тендер», «Прямые переговоры», «Расширение».
- Для всех типов используется одна общая воронка. Тип нужен для фильтра, а не для отдельного процесса.
- Название раздела «Тендеры» привычно, но исходный отчёт целиком считать реестром тендеров нельзя.
- Запуск — начало выполнения подтверждённой работы. Это отдельное событие после результата возможности.

## Канбан

| Этап | Когда применять |
| --- | --- |
| Запланировано | Возможность зарегистрирована, активная работа ещё не началась. |
| В работе | Уточняем условия, готовим предложение, подаём заявку или ведём переговоры. |
| Ждём решения | Предложение передано; дальнейший результат зависит от решения заказчика. |
| Выиграно | Подтверждён результат участия или конкретный заказ/объём работы. |

Победа требует подтверждённого результата или заказа; в карточке сохраняется краткое основание.
Подписанный договор, согласованный тариф или тестовый рейс сами по себе не означают победу.
Из любого этапа доступно «Закрыть» с причиной: «Проиграно», «Отменено», «Отказ от участия».
Закрытые карточки сохраняются и доступны отдельным фильтром, по умолчанию скрыты.
Повторное открытие возвращает карточку на выбранный активный этап и записывает событие.
Временная пауза — отметка и дата следующего контакта, без дополнительной колонки.

## Создание и поля

Для создания достаточно выбрать или добавить заказчика и указать короткое название возможности.
Начальный этап — «Запланировано»; остальные поля можно заполнить по мере уточнения.

| Поле | Простое правило |
| --- | --- |
| Заказчик | Ссылка на единую карточку компании; не копировать контакты в каждую возможность. |
| Название | Коротко различает проект или лот; например, «Доставка по Москве». |
| Статус | Одно значение из общей воронки; меняется с доски. |
| Потребность | Количество авто и требования: тоннаж, паллетность, кузов, температурный режим. |
| Тип доставки | «Городская» или «Экипажная»; допускается «Не уточнено». |
| Регион/город | Если влияет на предложение; несколько направлений можно описать внутри карточки. |
| Ожидаемый запуск | Дата, приблизительный период либо «Не уточнено». |
| Дедлайн подачи | Отдельная дата и при необходимости время; заполняется, когда такой срок есть. |
| Следующий шаг | Одно ближайшее действие и срок, если они определены. |
| Ответственный | Нужен при работе нескольких сотрудников; по умолчанию создатель карточки. |
| Тип возможности | Необязательно; уточняется без принудительного выбора при создании. |

Количество может быть точным, диапазоном или предварительной оценкой. Требования остаются коротким текстом.
Не превращать диапазон «5–8 авто» в точное число и не суммировать его как подтверждённый объём.
Ожидаемый запуск и дедлайн подачи имеют разные подписи и не подменяют друг друга.
Приблизительный период не преобразуется в точный день без уточнения пользователя.
Обязательность дополнительных данных вводится по действию: причина при закрытии, основание при победе.

## Работа прямо на доске

- На карточке видны заказчик, название, потребность, тип доставки, запуск и ближайшее действие.
- Последний комментарий показывается коротким фрагментом с датой и автором.
- Статус меняется перетаскиванием или списком — оба способа равноправны.
- «Добавить комментарий» открывает небольшое поле прямо на карточке; после сохранения обновляется фрагмент.
- Следующий шаг и его срок доступны для быстрого изменения без открытия полной карточки.
- Доступны поиск, фильтры по заказчику, типу доставки, ответственному и типу возможности.
- Просроченный следующий шаг или дедлайн отмечается явно; отсутствие даты не считается просрочкой.
- Полная карточка открывается для подробностей, документов и истории.

## Комментарии и история

Каждый новый комментарий хранится отдельной записью с фактическими датой, временем и автором.
В карточке доступна единая лента событий в хронологическом порядке, от ранних к поздним.
В ней различаются комментарии, изменения этапов, действия, результаты и изменения сроков.
«Последний комментарий» на канбане — последний именно комментарий, а не переход статуса.
Перенос карточки между колонками не заменяет и не скрывает последний комментарий.
Редактирование комментария отмечается, чтобы изменение текста не выглядело новым действием.
Комментарии возможности видны в её карточке и в истории заказчика со ссылкой на эту возможность.
Общие заметки заказчика хранятся у заказчика и не размножаются по всем его возможностям.

## Отчёт о работе за период

Отчёт строится по фактическим событиям выбранного периода без повторного заполнения таблицы.
В нём видны заказчик, возможность, сотрудник, дата, выполненное действие и полученный результат.
Создание, комментарий, подача предложения, смена этапа, подтверждение результата и закрытие — разные события.
Число комментариев не считать числом завершённых действий или выигранных тендеров.
Для каждой возможности можно раскрыть события периода и перейти к первоисточнику в карточке.
Текущий этап и следующие шаги показываются отдельно от событий периода.
Исторический срез «на конец периода» возможен только по реально сохранённым событиям с известными датами.
Для перенесённого отчёта недатированные заметки не создают фиктивную активность прошлых периодов.

## Перенос исходного отчёта

1. Сохранить все 29 исходных записей, исходные тексты A:E и номер строки как данные источника.
2. Для каждой строки определить заказчика и проверить, описывает ли она отдельную возможность или действующую работу.
3. Не создавать автоматически 29 подтверждённых тендеров. Неопределённые тип и этап оставить для уточнения.
4. Не удалять строки при объединении: сохранять связь итоговой карточки со всеми исходными строками.

Импортная заметка получает известную дату переноса как технический атрибут, а не дату исходного события.
До появления нового комментария на доске можно показать «Исходная заметка; дата неизвестна».
Тексты B и C нельзя сортировать как хронологическую историю или объявлять C самым поздним событием.
Цвета строк не имеют явной легенды: по ним нельзя назначать этапы или результаты.
Контроль завершения переноса: у всех 29 строк есть сохранённый источник и ссылка на карточку либо отметка «Требует уточнения».

## Проверка понятности концепции

Сотрудник создаёт возможность за два поля, видит ближайший шаг, меняет этап и пишет комментарий с доски.
Руководитель за выбранный период видит реальные действия и результаты без отдельного ручного отчёта.
Неизвестные даты, объёмы и результаты остаются явно неизвестными до уточнения.
