# Оформление кандидатов

Раздел «Оформление» находится в левом меню сразу под «Рекрутингом». Поддерживаются оформление в офисе с камерой и персональная ссылка кандидату. Платный OCR вызывается только после нажатия сотрудником; загрузка фотографии сама по себе не запускает распознавание.

Внутри раздела: «Анкеты», «Договоры», «Конструктор анкет», «Шаблоны договоров» и «Фотографии». Конструктор анкет собирает сведения и документы кандидата; конструктор шаблонов договоров задаёт текст и подстановки для договоров. Подробности о версиях, выдаче, печати и подписанных файлах — в [Договоры в оформлении кандидатов](RECRUITMENT_CONTRACTS.md).

## Работа рекрутера

1. В карточке существующего кандидата нажмите «Оформить кандидата» либо начните оформление в новой вкладке. Выберите опубликованную форму с нужным проектом, направлением и типом договора.
2. В офисе нажмите «Сфотографировать», наведите камеру и проверьте снимок. Можно переснять или выбрать готовый JPEG/PNG. Большие изображения уменьшаются до 2160 пикселей по каждой стороне; предварительный просмотр показывает именно отправляемый файл.
3. Загрузите снимок, нажмите «Распознать документ». Результат — редактируемый черновик: перенос в поля требует действия сотрудника. Можно заполнить всё вручную, если OCR не подключён или не справился.
4. Сверьте снимок и заполненные сведения, явно отметьте проверку документа. Проверка OCR не подтверждает подлинность паспорта или право на трудоустройство. Приложение не принимает решения о найме.
5. Сохраните поля и завершите проверку анкеты. Для обязательного документа проверенным должен быть последний загруженный снимок. Новый снимок требует новой проверки.
6. В подразделе «Фотографии» выберите проверенные фото и удалите их. Значения полей и отметки проверки сохраняются.

Для дистанционного оформления выдайте ссылку и скопируйте её кандидату. Ссылка действует семь дней, передаётся только адресату и погашается после отправки формы. Перевыпуск отзывает предыдущую ссылку. Изменение полей, загрузка или проверка фото сотрудником также отзывает действующую ссылку, чтобы поздняя отправка кандидата не перезаписала офисные правки. При необходимости сохраните изменения и выдайте новую ссылку.

Публичная форма не показывает уже заполненные сотрудником сведения и серверные фотографии. Кандидат заполняет поля, загружает документы и отправляет анкету; проверку и OCR выполняет сотрудник. Ссылка хранит секрет в URL fragment, а сервер — только его хеш. Токен, поля и снимки не записываются в localStorage. Автоматической отправки сообщений кандидатам нет.

## Конструктор и доступ

Конструктор доступен руководителю и администратору с правом на персональные данные компании. Можно создавать, копировать, редактировать и публиковать формы; выбирать тип оформления «Сотрудник», «ИП» или «Самозанятый»; добавлять и переставлять поля и документы; устанавливать обязательность и варианты списков. Неактивные формы недоступны для новых оформлений. Начатая анкета сохраняет неизменяемый снимок своей версии формы.

Внутренние рекрутеры и диспетчеры видят только созданные ими оформления. Руководитель и администратор видят оформления своей компании при наличии доступа к персональным данным. Внешним рекрутерам этот раздел недоступен. Каждое чтение фотографии, OCR, сохранение, проверка и удаление проверяют действующую сессию и права. Извлечённые паспортные сведения не добавляются в общие карточки кандидатов, сообщения, логи или события аудита.

## Три дня хранения

Срок оригинала — **72 часа от загрузки**, включая непроверенные фото. Продление срока или отключение правила через форму не предусмотрено. API закрывает доступ по наступлении срока. Фоновая очистка физически удаляет файлы каждые 60 секунд и при запуске приложения; остановленный сервер выполнит очистку после запуска. Ошибка одного файла не останавливает удаление остальных; повтор выполняется следующим проходом, в интерфейсе отображается предупреждение.

Фото находятся в отдельном приватном каталоге (0700, файлы 0600), в PostgreSQL только метаданные. При ручном удалении удаляются байты файла; в БД сохраняются автор, время, причина удаления и проверка. Периодический процесс удаляет также осиротевшие файлы после сбоев. Каталог необходимо исключить из резервных копий, синхронизации и архивов релиза: удаление рабочего файла не уничтожает чужие копии.

В production обязательно задайте абсолютный `ONBOARDING_PHOTO_DIR` **вне каталога приложения**, например `/var/lib/transport-onboarding/photos`, и предоставьте служебному пользователю доступ. Без корректного каталога другие разделы приложения продолжают работать, а загрузка новых фото недоступна. Не помещайте временные фото в web-root. Reverse proxy должен разрешать JSON-запросы загрузки до 14 МиБ и не записывать тела запросов/ответов. Данные формы ограничены 512 КиБ.

Срок удаления у внешнего OCR-провайдера — отдельный вопрос. Он не управляется нашим таймером. Для VK Cloud настройка и подтверждённые ограничения описаны в [VK_OCR.md](VK_OCR.md).

## Локальное приложение

Адрес: `http://127.0.0.1:18514/?section=recruitment`. Фото хранятся отдельно от постоянной локальной базы: `.local/onboarding-photos/`.

Для явного включения VK Vision локальный запуск читает `.local/local-app/ocr.json` с правами **0600**:

```json
{"provider":"vk","token":"<токен Vision API>"}
```

Это серверный файл, не поле анкеты. Не присылайте ключ в чат, не добавляйте его в исходники, публичные ссылки или `.env` клиента. Если файла нет, форма, камера и ручная проверка работают, а OCR отмечен как неподключённый. После настройки перезапустите приложение обычным `manage.cjs stop/start`. В рабочем окружении используется переменная `VK_OCR_TOKEN`.

Loopback-адрес доступен только на этом компьютере. Для реальных кандидатов с собственных телефонов потребуется установка на доступный HTTPS-домен, настройка того же API и приватного каталога фото. HTTPS нужен для встроенной камеры вне localhost. Локальная ссылка не является опубликованной формой в интернете.

## Проверка

Новые автоматические проверки используют временную PostgreSQL, синтетические аккаунты, изображения и камеру Chromium. Платные OCR-вызовы, реальные документы и реальные сообщения не используются.

```sh
cd recovered
npm run build
npm run test:recruitment:onboarding
npm run test:recruitment:onboarding:browser
```

Интеграционные проверки охватывают границы компании и роли, владение анкетой, одноразовые ссылки и их отзыв, снимки версий форм, конфликт изменений, обязательные поля, формат и лимиты фото, закрытие доступа по истечении 72 часов, фактическое удаление файлов и продолжение очистки после единичного сбоя. Browser-сценарий проверяет конструктор, камеру, пересъёмку, большой снимок, проверку, удаление, публичную форму и мобильный экран.

Во время расширенной проверки обнаружены устаревшие ожидания прежних `recruiter-role-integration.test.cjs` и `recruiter-role-browser.cjs`: один ожидает доступ только к одному проекту вместо общей базы компании, второй ждёт прежний `/recruitment` вместо `/recruitment/worklist`. Это существующий контракт общего рекрутинга из миграции 054; новая функция его не меняет. Актуальные проверки общего рекрутинга выполняются отдельно.
