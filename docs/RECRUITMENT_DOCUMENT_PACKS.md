# Комплекты оформления: ТК и перевозчики

В разделе «Оформление» по умолчанию открывается «Комплект» с переключателем «Водитель · ТК / Перевозчик». Прежние анкеты, конструкторы и отдельные договоры доступны в соседних вкладках.

## Работа рекрутера

Для водителя выберите кандидата или заполненную анкету. Кнопка «Заполнить по фото» использует форму «Водитель · ТК» с распознаванием паспортных полей через существующий адаптер VK Vision. Распознавание требует серверного токена; без него форма поддерживает фотографии и ручное заполнение. После проверки распознанных значений кнопка «Оформить комплект» переносит анкету в форму комплекта. Совпадающие поля заполняются один раз для всех выбранных документов.

Для перевозчика введите ИНН или ОГРН и выберите найденную организацию/ИП. DaData заполняет наименование, адрес, регистрационные реквизиты и доступные сведения о подписанте. По БИК заполняются банк и корреспондентский счёт. Расчётный счёт, контактный телефон и основание полномочий подписанта вводятся отдельно. Все полученные значения можно исправить перед выпуском.

Реквизиты собственной организации руководитель или администратор сохраняет для дальнейшего использования. Они привязаны к области ответственности и не включают персональные данные водителя или перевозчика.

Состав комплекта можно изменить: базовые документы выбраны заранее, остальные сгруппированы как дополнительные и проектные. После заполнения обязательных полей одна кнопка выпускает весь комплект. Если номер не указан, сервер присваивает его автоматически: `ТК-ГГГГ-00001` или `ПР-ГГГГ-00001`, отдельно по типу, области и году. Ручной номер также допустим.

Готовый комплект доступен в истории. Его можно целиком распечатать, сохранить как PDF через диалог печати или скачать HTML. Каждый документ начинается с новой страницы; отдельные документы доступны в разделе «Договоры» для регистрации подписанного экземпляра. Выпуск фиксирует текст и версии шаблонов, но не означает подписание или завершение проверки СБ.

## Шаблоны из Excel

Встроенный каталог содержит 37 шаблонов из «Оформление ТК.xlsx» и «Перевозчиков Оформление .xlsx»: 19 кадровых документов, две новые формы для пустых листов «Чек лист» и «Лист ознакомления», договор перевозчика, заявку и 14 проектных дополнений. Реестры людей и машин не превращены в шаблоны. Базовый выбор — восемь кадровых документов либо основной договор перевозчика; акт передачи ТС и разовая заявка выбираются по необходимости.

Установка добавляет недостающие шаблоны как обычные опубликованные редактируемые версии. Повторная установка не заменяет правки пользователя и не восстанавливает удалённые им шаблоны. Установка кадрового каталога также добавляет готовую OCR-анкету водителя. Каталог и описание преобразования находятся в `integrations/recruitment-contract-catalog/`.

Персональные сведения из исходных файлов не включены в значения по умолчанию. Формулы Excel заменены объявленными полями. Исходные условия сохранены с примечаниями: спорные тарифы Оптиком требуют согласованного текста; налоговый режим и срок оплаты заявки не угадываются. Установка шаблона не подтверждает правовую применимость исходных условий к конкретному договору.

## Сервер и сохранность данных

DaData вызывается только сервером по фиксированным официальным адресам `findById/party` и `findById/bank`. Ключ задаётся через `DADATA_API_KEY`. Локальный launcher также читает приватный `.local/local-app/dadata.json` с полями `provider: "dadata"` и `apiKey`; файл должен иметь права `0600`. Ключ не возвращается браузеру и не хранится в исходном коде. Подключение проверялось по документации https://dadata.ru/api/find-party/ и https://dadata.ru/api/find-bank/ .

Перед внешним запросом и после него проверяются текущие права сотрудника. Действуют таймаут, лимит ответа и ограничение частоты запросов. Содержимое реквизитов, OCR и документов не записывается в аудит.

Выпуск комплекта выполняется одной транзакцией. Любая ошибка откатывает все его документы. Ключ повторного запроса предотвращает дубли при двойном клике или повторе после обрыва соединения. Версии шаблонов проверяются перед выпуском. Снимки комплекта и происхождение документов защищены от перезаписи на уровне БД.

Миграция `068_recruitment_contract_packs.sql` добавляет каталог, комплекты, настройки организации и счётчики номеров. Миграции 066 и 067 не изменяются. Исходные Excel, прежние договоры и кандидаты сохраняются.

## API

Префикс: `/api/v1/recruitment/contracts`. Все маршруты требуют сессию сотрудника и доступ к персональным данным; ответы имеют `Cache-Control: no-store`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /packs/catalog` | Шаблоны, общий набор полей, конфликты и предзаполнение; параметры `responsibilityScopeId`, `kind`, необязательные `candidateId`, `onboardingSessionId`, `templateIds` через запятую |
| `POST /packs/install` | Установка отсутствующих шаблонов: `{responsibilityScopeId,kind?}`; руководитель/администратор |
| `PUT /packs/settings` | Сохранение реквизитов организации: `{responsibilityScopeId,version,values}`; руководитель/администратор |
| `POST /packs` | Выпуск: `{responsibilityScopeId,kind,templateIds,templateVersions,values,number,date,idempotencyKey,candidateId?,onboardingSessionId?}` |
| `GET /packs/:id` | Комплект и сохранённые документы |
| `POST /party-lookup` | Реквизиты организации/ИП: `{responsibilityScopeId,query}` |
| `POST /bank-lookup` | Реквизиты банка по БИК: `{responsibilityScopeId,query}` |

В существующем `GET /context` также возвращается история `packs`.
