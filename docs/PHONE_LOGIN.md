# Вход по телефону и паролю

## Поведение

Один экран входа работает в обычном браузере, Telegram и MAX. Администратор выбирает сотрудника в разделе «Сотрудники», указывает номер и выдаёт пароль. При сбросе старый пароль и все сессии сотрудника перестают работать. Роли и области доступа выдача пароля не расширяет. Пароль показывается один раз; приложение не отправляет его сотрудникам автоматически.

Телефон нормализуется в международный формат (`8 900 123-45-67` → `+79001234567`). Каждый номер принадлежит одной учётной записи. Приложение запоминает последний введённый номер на устройстве, пароль не сохраняет. Для менеджера паролей используются стандартные атрибуты формы. Короткая сессия хранится в sessionStorage и проверяется сервером через `/me` при перезагрузке; SDK мессенджера для входа не требуется. При выбранном «Запомнить вход на этом устройстве» HttpOnly cookie восстанавливает вход и автоматически обновляет сессию. Срок — 30 дней с продлением при использовании, максимум 90 дней от первого входа. Подробности и подключение уведомлений: [NOTIFICATIONS.md](NOTIFICATIONS.md).

При открытии внутри мессенджера пустое поле сначала заполняется номером уже связанной учётной записи, если сервер смог проверить подпись initData. Иначе приложение запрашивает согласие на передачу контакта. MAX возвращает номер через Bridge; Telegram передаёт контакт webhook бота, после чего приложение получает свой номер по подписанному initData. Без согласия или при недоступности SDK можно ввести номер вручную. Автозаполнение не заменяет проверку пароля и не создаёт связь с аккаунтом мессенджера.

## API

- `POST /api/v1/auth/password` — `{phone,password,rememberDevice?}` → стандартная сессия, канал `web`, и защищённая cookie при сохранении входа.
- `POST /api/v1/auth/refresh` и `/auth/device-status` требуют cookie, разрешённый Origin и `X-Session-Refresh: 1`; секретный ключ не возвращается в JSON.
- `POST /api/v1/access/users/:userId/password` — `{phone}` → `{userId,phone,password,issuedAt}`; требуется действующая сессия администратора и управление всеми областями сотрудника.
- `POST /api/v1/auth/phone-hint` — `{provider,initData}` → `{phone:null|string}`; сервер проверяет подпись, срок действия и принадлежность номера запрашивающему пользователю.
- `/employees` — дополнительные поля `phoneLoginEnabled`, `phoneMasked`, `canIssuePassword`.

## Хранение и ограничения

Миграция `018_phone_password.sql` добавляет `phone_credentials` и `phone_login_attempts`. Пароли хранятся с индивидуальной случайной солью и scrypt; исходный пароль не попадает в аудит. Пять неудачных попыток за 15 минут блокируют вход по номеру на 15 минут, счётчик переживает перезапуск сервиса. Дополнительно действует ограничение запросов с одного IP. Ошибка входа не сообщает, существует ли номер.

Контакты Telegram принимаются только через защищённый webhook, из свежего личного сообщения пользователя с его собственным `contact.user_id`. Подсказка хранится в памяти не более пяти минут; объём ограничен. Номер чужого или пересланного контакта не используется.

## Проверка и сборка

```sh
npm test --prefix recovered
npm run test:integration --prefix recovered
npm run build --prefix recovered
```

Для браузерной проверки на синтетических данных: `node tests/local-test-server.cjs`. Скрипт поднимает отдельный PostgreSQL и выводит локальный адрес и временные тестовые доступы. Никакие production-переменные окружения не читаются.

## Развёртывание

`recovered/infra/deploy/apply-phone.py` проверяет контрольные суммы текущего API и web-root, сохраняет БД, runtime, окружение и Nginx, применяет добавочную миграцию и атомарно заменяет сборку. При неудаче возвращает предыдущий код и конфигурацию. Миграция при откате сохраняется, чтобы не удалять новые учётные данные.

Операционные сведения о выполненном развёртывании добавляются после успешной проверки сервера. Пароли и токены в эту документацию не включаются.
